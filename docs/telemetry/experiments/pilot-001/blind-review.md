## lite

Call 1:

- [major] brief_conflict_unflagged, spec §3/§6 SD3, requirements F1/F4: The request says notes are visible to members of any project; the spec reverses this to own-project-only. It is recorded as an assumption, but the plan has no step to get the owner's yes before building, and nothing blocks the build until Gate 1.
- [major] brief_conflict_unflagged, spec SD2 and plan T1-T3: The request asks for a new table, which AD-09 disallows (comments out of scope). The plan builds the migration and service before the amendment is confirmed. If Gate 1 rejects it, T1-T4 are rework.
- [major] contradiction, spec §3 non-goals vs request bullet 'every project member can edit notes they can see': The request's 'only the PM now, members later' is handled by a policy-map change, but the spec's claim that the handler has no role check is untested. The authorization-matrix test hard-codes PM-only, and no seam exists for an owner predicate. The deferred feature is not designed.
- [major] ambiguity, request 'recent notes first' and 'pinned note' vs F1/UI: Pinning sorts by 'pinned desc, then createdAt'. The UI shows 'updated' time while sort uses createdAt, and the request's 'recent' is not defined. Edited notes do not move, which may surprise users.
- [blocker] ordering, plan T3 vs T4 and Dependencies: T4 route tests need real resolvers and fake AuthDependencies, but T4 depends on T2/T3 while the service needs a database that T1 supplies. T3 lists dependencies T1, T2 correctly, but T6 depends only on T5. The screen runs on prototype-store functions, so no contract is verified against the real API.
- [blocker] missing_step, plan T3 / api.md transaction boundary: The plan specifies `inMutationTransaction(db, async () => {}, recheckEpic, ...)` as 'adapt to the real API' without knowing its signature. The no-op lockResource, the filtered client inside the tx and the retry semantics are unverified. An implementer model cannot resolve this, so the build may stall.
- [major] data_model, data-model.md / T1 migration SQL: The composite FK (project_id, epic_id) -> epics(project_id, id) needs a unique constraint on epics(project_id, id). The plan does not verify or add it. The pin swap's unique index is also not DEFERRABLE, so the order unpin-then-set matters. A PATCH that sets pinned=true runs updateMany unpin first, which is fine, but the swap relies on read-committed behavior not documented.
- [minor] data_model, T1 Prisma schema: The Prisma schema cannot express the partial unique index, so `prisma migrate dev`/diff will see drift. The plan says nothing about drift handling or the schema-parity test.
- [major] contradiction, api.md GET tenancy vs archived rule: Reads of archived projects are 404, so notes in an archived project vanish for the whole team, while the UI shows only the 404 'epic not found' copy. This is likely wrong context for users, and E14 treats it as intended without product confirmation.
- [major] contradiction, api.md Authorization order vs F4/E8: A non-member Developer gets 403 on writes while a non-member PM gets 404, which is a minor role-existence oracle. The spec states the policy's existence is not secret, but the 'no existence oracle' claim in E8 and the threat list is internally inconsistent.
- [major] test_gap, plan T6: F6, E21-E23 and E25 are manual checks only, with no DOM test runner. Role-based control hiding (E22), the main permission requirement in the UI, has no automated test, and 'smoke' does not cover it.
- [major] test_gap, plan T3 pin-race.test.ts: The race test asserts at least one success, but the P2002 or serialization retry paths are not forced deterministically. With three retries and unpin-first writes, the 409 pin path may never be exercised, so the CONFLICT_STATE mapping is untested.
- [major] ambiguity, api.md PATCH: A no-op PATCH, or pinned=true on an already pinned note, bumps version and also unpins nothing. But 'the previously pinned note is touched' text contradicts E28 'no other note changes'. Also the PATCH unpin loop excludes this id, which makes them consistent only for different notes.
- [minor] ambiguity, api.md EpicNoteInput / trim: The body is trimmed in zod, but the stored value, line breaks and internal whitespace, and trim semantics for Unicode whitespace vs PostgreSQL char_length, are not specified. A trimmed 500-char body versus CHECK on untrimmed input could disagree.
- [minor] scope_creep, spec SD8 and plan T7: The Attacker/Tester/Maintainer lenses were skipped on a High-tier change, and the plan's T7 adds branch-state, guide and architecture bookkeeping that the request did not ask for.
- [major] missing_step, plan T4 / Close-out: The feature is not reachable from the running app: wiring waits on W4/W5, which are not delivered here. The request's 'add the endpoint' is therefore only partly satisfied, and the plan treats it as post-merge without a dependency check or owner confirmation.
- [minor] brief_conflict_unflagged, request paths vs plan: The request names apps/api and apps/web; the plan replaces them with src/be/api and src/fe based on C8. This is flagged in the spec but is an assumed deviation whose reversal would invalidate every file path.
- [minor] security_permissions, T7 step 3: Step 3 sends a message to the W4/W5 owners. It is marked GATE, but the plan does not say who delivers it or what channel is used, so an implementing model may skip or improvise it.

E8's 'byte-identical body apart from requestId' needs a specific assertion that the plan does not describe. No test covers PATCH/POST pinned race at the route level (409 mapping to HTTP).

No task makes the `EpicNotes` implementation be constructed with a database client (`createEpicNotes(deps)` deps are undefined). - [minor] missing_step, T5 / T6: The front-end prototype store has no notion of the current user's role for the 'PM-only throws FORBIDDEN_ROLE' rule, and the plan does not say how the data layer learns the role. - [minor] ambiguity, api.md EpicNoteInput / UI counter: Zod trims then counts code points, but the UI counter and disabled-Save rule count the raw text, so a body of 500 characters plus trailing spaces shows over-limit in the dialog while the server accepts it. The 'Provide body or pinned' error is placed on field `body`, which is odd when only `pinned` is expected.
- [minor] scope_creep, spec SD2 / data-model.md / T7: The 'keep it light' request becomes a High-risk tier with a new package, a new table, composite FKs, OpenAPI, a partial index, a migration and architecture doc proposals.
