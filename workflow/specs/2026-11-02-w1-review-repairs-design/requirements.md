# Requirements

## Functional

- **F1 Authorization ownership resolution:** For every one of the 57 policy entries, the table-driven authorization test exercises the declared resource/predicate mapping. The canonical resolver maps the route operation to an owned resource and returns a discriminated result from storage; a client-supplied project scope is never trusted. A missing/deleted resource returns `NOT_FOUND` for reads and resource-targeted membership predicates; a recognized archived project returns `CONFLICT_STATE` for writes and `NOT_FOUND` for reads. No handler runs after a failed predicate.
- **F2 Recursive request-facing visibility:** For the allowlisted request-facing models `Project`, `ProjectMember`, `Checkpoint`, `Epic`, `Sprint`, `Task`, `TaskEvent`, `AiProposal`, `ProposalEpic`, `AiSession`, `LlmCall`, `ActivityItem`, `ItemSummary`, `Standup`, and `ProjectDigest`, the required model/relation matrix test covers root, singular, to-many, nested `select`/`include`, `_count`, `aggregate`, and `groupBy` reads. All results exclude soft-deleted rows and records belonging to archived projects; nullable `AiSession`/`LlmCall` rows are visible only when `projectId` is null or the related project is active. Explicit maintenance access remains unavailable.
- **F3 Valid unique reads:** Scalar `{ id }` selectors and every schema compound key are normalized exactly: `ProjectMember.projectId_userId → { projectId, userId }`; `ProposalEpic.proposalId_index → { proposalId, index }`; `ActivityItem.projectId_uploadedBy_itemType_repo_externalId → { projectId, uploadedBy, itemType, repo, externalId }`; `ItemSummary.itemId_contentHash_guardVersion_promptVersion → { itemId, contentHash, guardVersion, promptVersion }`; `Standup.projectId_developerId_standupDate → { projectId, developerId, standupDate }`. Missing members, unknown keys, nulls, wrong types, and prototype-like keys fail closed before Prisma with `NOT_FOUND` 404 at the HTTP boundary. A hidden row behaves as not found; `findUniqueOrThrow` raises the existing `NOT_FOUND` sentinel.
- **F4 Resolvable OpenAPI:** Generated request and response `$ref`s have matching entries under `components.schemas`; the registry is canonical, duplicate names with different schemas fail generation deterministically, duplicate identical schemas are idempotent, and the generated document contains no unresolved internal references.
- **F5 PR #6 contract alignment:** The policy map, `docs/architecture/contracts.md` §3.2/§3.4/§3.5/§3.6, `docs/architecture/agile-platform-architecture.md` §4/§7/§13, and W1 contract tests represent endpoint 6 as a page of `ProjectDetail`, endpoint 42 as `PROJECT_FACTS_READ` at `GET /api/projects/{id}/facts` for PM and Dev Lead members, endpoint 36 as a Tier 1 PM surface, and standup dates of today or the next Singapore working day only. The old endpoint-42 route is not registered and returns 404.

## Non-functional

- **N1 Regression evidence:** Named tests map to F1-F5 and E1-E25, including a table-driven 57-policy authorization test, model/relation visibility matrix, route-level HTTP error tests, normative-doc parity, OpenAPI dereference checks, weekend/date boundaries, and a deterministic race test; `npm test` and `npm run typecheck` pass before review.
