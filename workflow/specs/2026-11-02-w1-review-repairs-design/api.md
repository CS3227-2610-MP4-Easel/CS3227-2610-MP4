## Resource resolver matrix

| Policy predicate | Resource keys and owner source | Resolver owner |
|---|---|---|
| MEMBER | `projectId`/project `id` → project; child `id`/`proposalId`/`standupId` → stored project | `core`, `proposals`, `dev` |
| MEMBER_OR_ASSIGNEE | task `id` → task project and assignee user | `core` |
| SELF | `standupId`/`itemId`/`summaryId`/`sessionId`/usage query → stored developer/uploader/user | `dev`, `llm-gateway`, `auth` |
| ADDER | project `projectId` plus target `userId`; target role is loaded before role-to-role rule | `auth` |
| MEMBER_PROJECTS | principal user ID → all active project memberships | `auth` |

All resolvers return a not-found result for deleted/archived/cross-project objects. No resolver accepts a caller-provided project ID as authoritative when a resource ID is present.

`AuthorizationScope` is `{ principal, resolved, tx }`, where `tx` is a Prisma transaction client. Reads execute resolution and handler read under one repeatable-read transaction. Mutations acquire a row lock on the resolved project/resource, re-check membership, archived state, ownership, and expected version, then commit the write; a failed re-check rolls back the transaction. Archived reads are hidden as 404, while archived writes reach the project write guard and return `CONFLICT_STATE` 409.

`VISIBILITY_POLICY` in `packages/db/src/visibility.ts` is the maintained immutable registry for the relation matrix above. Every allowlisted model has one entry declaring `softDelete: boolean`, `projectScope: "required" | "nullable" | "root"`, and its visible relation paths; adding a Prisma model without an entry fails the DB parity test. The transformer applies only entries from this registry.

## Consistency, failure, and audit rules

- Authorization-only reads use one database snapshot from resolution through handler read. Mutations perform the ownership, membership, archive, and version checks again inside the mutation transaction before writing; a race returns `NOT_FOUND`, `CONFLICT_STATE`, or `CONFLICT_VERSION` and writes nothing.
- No new audit table or persisted field is required: existing task events and AI session records remain unchanged. Resolver failures do not log IDs or untrusted text beyond the request ID and stable error code.
- OpenAPI generation is build-time and atomic: a conflict or unresolved ref produces no document output and no fallback document is accepted. There is no data migration or rollback step for this change.
- The endpoint-42 compatibility decision is deliberately breaking within this pre-release branch: the old route is absent, and contract parity asserts the new method, path, operation ID, policy key, roles, and response schema against both `packages/contracts/src/policy.ts` and the two normative architecture files.
