# Operations and contracts

| Operation | Caller / trust | Inputs and exact validation | Success | Failure and side effects |
|---|---|---|---|---|
| Manual development deployment evidence | Owner of the protected `development` deployment; Vercel UI and fixed smoke responses are external evidence | Obtain `commit` and `pushTimestamp` from the GitHub merge commit (`committer.date`, UTC), and obtain canonical `project` and `alias` from the code-owned `tier-manifest.json` `dev` row. Record deployment ID, `READY` state, alias ownership, `createdAt` strictly after `pushTimestamp`, and `checkedAt`. Use HTTPS requests to that exact alias with redirects disabled; any `3xx` fails. Fixed requests: `GET /api/health` must return `200` with body status `UP`; authenticated `GET /api/me` with the protected dev smoke identity must return `200`; the foreign-project token must return `401`; confirm the inspected deployment is the `dev` tier. Record only statuses, timestamps, IDs, and fixed labels—never response bodies, credential URLs, tokens, or secret values. | Produces a redacted T4 evidence object for the branch state | Missing, mismatched, stale, non-ready, alias-reassigned, redirected, wrong-target, or failing evidence leaves T4 incomplete; no production deployment may proceed |
| `runSeed(env)` | Local/dev/test operator or fixed non-production job; env is untrusted configuration | Production entry point accepts no client-injection parameter. Tier must be `local`, `dev`, or `test`; `DATABASE_URL` must parse as `postgres:` URL; host, database name, and `NEON_PROJECT` observation must match the immutable target map for the tier. A separate unexported test factory may receive a fake client only after the same validation | Seeds the deterministic dataset and disconnects a constructed client | Invalid tier, missing/malformed URL, host/database/project mismatch throws before any client construction or write occurs |
| `runProductionMigration(env, root, executor?)` | Protected production job only; env is CI-controlled | Target validation includes parsed `DIRECT_DATABASE_URL` host, database name, and `NEON_PROJECT` observation against the immutable production target. Discover the complete set of `*/migration.sql` files below the committed migrations directory and require exact set equality with manifest paths; every raw file checksum matches its line; paths are normalized, sorted, unique, and lowercase-hex checksums. `executor` has signature `(file, args, options) => Promise<{ stdout: string; stderr: string }>` and receives an allowlisted environment | Runs Prisma validation, then forward-only migration deploy | Any target, manifest, read, parse, or checksum error throws before either Prisma command; executor receives exactly the allowlisted process keys plus temporary `DATABASE_URL`, never `DIRECT_DATABASE_URL`, Vercel token, Firebase credentials, or unrelated secrets |
| `validateTierResources(env)` | Application startup configuration | `loadAuthSettings` unconditionally validates the complete resource set for `dev` and `prod`, even when fields are absent. Dev requires the complete dev resource fixture, `VERCEL_ENV=preview`, and `VERCEL_GIT_COMMIT_REF=development`; prod requires the complete prod resource fixture, `VERCEL_ENV=production`, and `VERCEL_GIT_COMMIT_REF=main`; preview rejects all data credentials and accepts non-protected source refs | Returns `void` | Missing or mismatched fields throw only the setting name and never its value |

Security rules: no operation logs URLs, tokens, connection strings, response bodies, or secret values. Manual T4 evidence is collected by the owner from the Vercel UI and fixed requests against the inspected `development` alias; no Vercel deployment token is used by repository workflows or application runtime.

The owner must recheck the deployment ID, exact alias ownership, and `READY` state after the smoke requests. If the alias changes, the evidence is invalid and the owner must inspect the replacement deployment before recording T4.
