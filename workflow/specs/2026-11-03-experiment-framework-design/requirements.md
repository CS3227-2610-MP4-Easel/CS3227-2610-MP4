# Requirements

Ordered so that a requirement comes after anything it depends on. "Harness" is the `exp` command line ([api.md](api.md)). "Operator" is the person running it. Mechanics, formulas and the planned arms are in [runtime.md](runtime.md).

## Functional
| ID | Requirement | Acceptance criterion |
|---|---|---|
| F1 | An arm is a JSON file `arms/<arm-id>.json`; adding or changing an arm needs no code change. Ids match `[a-z0-9-]{3,24}`, path fields are relative with no `..`, `plugins` resolve only under `EXP_ROOT/plugins/`, and `isolation_ignore` may not name a plugin or hook | Given a new valid arm file When `exp check` runs Then it is valid; given `"plugins": ["../x"]` Then exit 3 |
| F2 | A task is a folder `tasks/<task-id>/` with `task.json` and `brief.md` (required). `answer-sheet.md` is required when any experiment using the task has `answer_mode` `sheet`. `seeded-issues.json` is optional; without it grading skips seeded recall | Given a sheet-mode experiment and a task without `answer-sheet.md` Then `exp check` exits 3 naming the file; given a bank-mode experiment and no seeded file Then `exp check` is clean |
| F3 | Each run executes in its own local clone made with `--no-hardlinks`, checked out at the task's `base_commit`, with no remotes and an empty hooks path, under `worktrees_root`. The harness then removes `.claude/skills`, `.claude/agents` and `.claude/settings*.json` from the clone, copies in from the main checkout only the arm's listed skills and agents, and keeps only the files in the arm's `instruction_files` | Given a prepared clone Then `git remote` is empty, its `.claude/` holds exactly the arm's skills and agents, and two active runs have different clone paths |
| F4 | Isolation: every agent invocation, first and resumed, carries `--setting-sources project`, `--strict-mcp-config` with the arm's MCP set (default none) and `--plugin-dir` per arm plugin. A probe invocation before the task prompt, launched with `--include-hook-events`, must return an init record whose skills, plugins, agents, MCP servers and tools equal the expected sets as sets (derivation in runtime.md, built-ins included), and a stream whose hook events name only SessionStart hooks that the arm's plugins declare; any difference aborts the run | Given a recorded init record with one extra plugin, or a hook event naming an undeclared hook, Then `isolation_mismatch`, exit 4, and no task prompt is sent; given a resume launch Then its argument list carries the same isolation flags as the first launch |
| F5 | The driver appends the completion instruction to the arm prompt, ends the run when the final assistant message's last non-empty line equals `EXP-DONE`, and treats any other non-empty final message as an operator-facing question (rules in runtime.md § Driver) | Given the fixtures `done`, `marker-quoted-mid-text`, `question-then-marker-last-line`, `marker-then-question-last-line`, `question`, `blank` Then the classifier returns done, question, done, question, question, empty |
| F6 | One `exp run` process runs up to `max_parallel` runs and survives pauses; a killed run resumes with `exp run --continue <run-id>` from `state.json` (atomic writes; fields in data-model.md) after repeating the F15 check, the manifest hash comparison and the probe | Given a run killed mid-turn Then `--continue` reloads spend and session id and sends the continue prompt; given an arm file edited since the manifest Then `--continue` exits 7 |
| F7 | `sheet` mode: the answerer returns `{covered, answer}` from `answer-sheet.md` only; when `covered` is false the harness replies with the fixed assumption text | Given a sheet-silent question Then the reply is byte-equal to the fixed text and the question has `source=assumption` |
| F8 | `bank` mode: a question is matched by normalised exact text (algorithm in runtime.md); otherwise a queue item is created with an optional model-suggested duplicate. The operator answers with `exp answer`, or `--same-as <bank-id>`; every run paused on that queue item resumes | Given the pair table in edge-cases E33 Then match results equal the expected column; given a suggestion Then it is never applied without `--same-as` |
| F9 | `exp extract` copies the transcripts (main and subagent) into the run folder, hashes them, and writes one event per distinct assistant message id with agent id, parent id, model, four token buckets, tools, start, end and cost (rounding in runtime.md) | Given the fixture transcript with repeated message ids and a stub `pricing.json` Then the row count equals the distinct id count and token sums and the run cost equal the hand-computed fixture values |
| F10 | Each event gets a phase from the arm's `phase_map` using the precedence in runtime.md; unmatched events get `other` | Given the precedence fixtures Then each event's phase equals the expected column |
| F11 | Every operator-facing question is stored with run, turn, text, source (`sheet`, `bank`, `assumption`, `operator`) and, after grading, a seeded-issue id plus an optional alternate id | Given a graded pilot run Then each question row has one source and at most one `issue_id` and one `issue_alt` |
| F12 | `exp grade` finds the spec and plan by the arm's `artifact_globs`, then writes: lint error counts (only for arms with `lint` true), seeded-issue outcomes, two-call rubric scores for the spec and the plan, review rounds and fix iterations (formulas in runtime.md); artifacts pass a credential scan before the judge sees them | Given the calibration artifacts Then judge scores are ordered good over mediocre over bad and fall in their stored bands; given an arm with `lint` false Then the lint fields are empty and flagged |
| F13 | `exp report` writes `runs.csv`, `events.csv` and `medians.csv` under `docs/telemetry/experiments/`, prints a verdict per arm pair (`dominated`, `tradeoff`, `inconclusive`) by the rule in runtime.md, and declares no winner | Given the worked tables in runtime.md § Reports Then medians, geometric means and verdicts equal the stated values |
| F14 | Run and batch USD ceilings and timeouts come from the experiment file. The check uses spend computed from events and `pricing.json`; each invocation gets `--max-budget-usd` equal to the run ceiling minus spend so far; a CLI budget stop maps to `budget`. An arm model missing from `pricing.json` refuses to start | Given a stub CLI scripted to emit costs Then the run aborts `budget` at the first turn end at or above the ceiling and `overshoot_usd` is recorded; given a CLI budget-stop result Then the reason is `budget`, not `crash` |
| F15 | An experiment file must be committed and unmodified (`git ls-files` tracked, no diff against HEAD) before `exp run` starts; its blob hash is stored in every manifest | Given an uncommitted or modified file Then exit 7 and no run starts |
| F16 | The framework ships a synthetic pilot task with an answer sheet and at least 6 seeded issues, each with an `anchor` string found in the brief or sheet, covering all six categories `collision`, `contradiction`, `missing_limit`, `vague_term`, `wrong_path`, `missing_error` (extra categories are allowed) | Given `tasks/pilot-pinned-note/seeded-issues.json` Then it has 6 or more entries, all six categories, and every anchor is found |
| F17 | Containment: the child process gets only the environment allowlist in runtime.md; `WebFetch` and `WebSearch` are denied unless the arm lists them (shell network access is not blocked). At each turn boundary the harness compares `.git/config` and `.git/hooks` of the main repo, `~/.claude/settings.json`, the batch's config files (hashed at batch start) and the run's own state files against their recorded hashes; a difference aborts every run with a turn in flight as `containment` | Given a fake agent that appends to the main `.git/config` Then the run ends `aborted`, reason `containment`, exit 10 and the path is listed |

## Non-functional
| ID | Category | Requirement | Acceptance criterion |
|---|---|---|---|
| N1 | Accuracy | Extracted arm cost matches the CLI's reported total, summed over the arm's own invocations (probe, answerer, matcher and judge excluded) | At most 2 percent difference on every run that has a reference total; T2 records the field name; T9 fails if fewer than 6 of 9 pilot runs have a reference total |
| N2 | Reproducibility | The manifest holds everything that fixes a run's inputs | `manifest.json` stores base commit, hashes of the arm, plugin contents, task, experiment, answer sheet, rubric, pricing, config and prompts, harness and CLI versions, model ids, bank snapshot hash at start |
| N3 | Security | No credential pattern (runtime.md table) in any committed file, in artifacts sent to the judge, or in questions shown to the operator | `exp check --secrets` and `exp report` exit 9 on a positive fixture and pass on the negative fixtures (a git sha, a base64 image header) |
| N4 | Isolation | Answerer, matcher and judge run with no tools, a neutral temp directory, no session persistence, `--setting-sources` limited to none, `--strict-mcp-config` and no plugins, and receive only their stated inputs | The prompt builders' unit tests assert no repo path, key or arm id; a launch test asserts the flags; a probe of these launches shows empty tool and MCP sets and no hook events |
| N5 | Fairness | Time terms are measured in milliseconds and rounded once each: `wall_s`, `wait_s`, `answerer_s`; `agent_s = wall_s - wait_s - answerer_s` from the rounded terms. Answerer and matcher time counts only while the run is `running`, so it never overlaps `wait_s` | A synthetic timeline with known gaps, including an answerer call that ends exactly when the wait starts, asserts exact values |
| N6 | Overhead | Model calls outside the arm are costed apart | `runs.csv` has `arm_cost_usd`, `answerer_cost_usd`, `matcher_cost_usd`, `judge_cost_usd`, `probe_cost_usd`; arm cost excludes the other four |
| N7 | Portability | Windows 11 with Node 20 or later, no shell: the harness refuses `.cmd`, `.bat` and `.ps1` launchers (exit 3), spawns a native executable with an argument array, and passes prompts through stdin; POSIX is best effort | A launch test puts `& \| ^ " %` in every argv value (session id, plugin path, model, run id parts) and in a question; the child receives each unchanged |
| N8 | Resilience | Crashes leave usable data; extraction is repeatable | `exp extract` run twice gives byte-identical files; a fault-injection hook in the atomic writer proves a kill during any write leaves the previous file intact |
