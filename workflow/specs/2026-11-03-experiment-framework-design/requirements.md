# Requirements

Ordered so that a requirement comes after anything it depends on. "Harness" is the `exp` command line ([api.md](api.md)). "Operator" is the person running it. Mechanics, formulas and the planned arms are in [runtime.md](runtime.md).

## Functional
| ID | Requirement | Acceptance criterion |
|---|---|---|
| F1 | An arm is a JSON file `arms/<arm-id>.json`; adding or changing an arm needs no code change. Ids match `[a-z0-9-]{3,24}`, path fields are relative with no `..`, and `plugins` resolve only under `EXP_ROOT/plugins/` | Given a new valid arm file When `exp check` runs Then it is valid and `exp run` accepts it; given `"plugins": ["../x"]` Then exit 3 |
| F2 | A task is a folder `tasks/<task-id>/` with `task.json` and `brief.md` (required). `answer-sheet.md` is required when any experiment using the task has `answer_mode` `sheet`. `seeded-issues.json` is optional; without it grading skips seeded recall | Given a sheet-mode experiment and a task without `answer-sheet.md` Then `exp check` exits 3 naming the file; given a bank-mode experiment and no seeded file Then `exp check` is clean |
| F3 | Each run executes in its own local clone of the repo checked out at the task's `base_commit` (separate `.git`, no hooks copied), under `worktrees_root` outside the repo | Given two active runs Then their clone paths differ and `.git/hooks` of a clone holds only the sample files |
| F4 | Isolation: every agent invocation uses `--setting-sources project`, `--strict-mcp-config` with the arm's MCP set (default none) and `--plugin-dir` per arm plugin. A probe invocation before the task prompt must return an init record whose skills, plugins, agents, hooks, MCP servers and tools equal the arm manifest as sets; any difference aborts the run | Given a recorded init record with one extra plugin Then the unit test reports `isolation_mismatch`, exit 4, and no task prompt is sent |
| F5 | The driver appends the completion instruction to the arm prompt, ends the run when the final assistant message's last non-empty line equals `EXP-DONE`, and treats any other non-empty final message as an operator-facing question (rules in runtime.md § Driver) | Given the fixtures `marker`, `marker-in-quote`, `marker-plus-question`, `question`, `blank` Then the classifier returns done, question, question, question, empty |
| F6 | One `exp run` process runs up to `max_parallel` runs and survives pauses; a killed run resumes with `exp run --continue <run-id>` from `state.json` (atomic writes) | Given a run killed while writing `state.json` Then the previous valid state loads and `--continue` resumes with the spend so far |
| F7 | `sheet` mode: the answerer returns `{covered, answer}` from `answer-sheet.md` only; when `covered` is false the harness replies with the fixed assumption text | Given a sheet-silent question Then the reply is byte-equal to the fixed text and the question has `source=assumption` |
| F8 | `bank` mode: a question is matched by normalised exact text; otherwise it is queued with an optional model-suggested duplicate. The operator answers with `exp answer`, or `--same-as <bank-id>`; every run paused on that question resumes | Given the pair table in edge-cases (E14, E16) Then match results equal the expected column; given a suggestion Then it is never applied without `--same-as` |
| F9 | `exp extract` copies the transcripts (main and subagent) into the run folder, hashes them, and writes one event per distinct assistant message id with agent id, parent id, model, four token buckets, tools, start, end and cost | Given the fixture transcript with repeated message ids Then the row count equals the distinct id count and token sums equal the independently counted fixture totals |
| F10 | Each event gets a phase from the arm's `phase_map` using the precedence in runtime.md; unmatched events get `other` | Given the precedence table fixtures Then each event's phase equals the expected column |
| F11 | Every operator-facing question is stored with run, turn, text, source (`sheet`, `bank`, `assumption`, `operator`) and, after grading, a seeded-issue id plus an optional alternate id | Given a graded pilot run Then each question row has one source and at most one `issue_id` and one `issue_alt` |
| F12 | `exp grade` writes: lint error counts, seeded-issue outcomes, two-call rubric scores for the spec and the plan, review rounds and fix iterations (formulas in runtime.md); artifacts pass a credential scan before the judge sees them | Given the calibration artifacts Then judge scores are ordered good over mediocre over bad and fall in their stored bands |
| F13 | `exp report` writes `runs.csv`, `events.csv` and `medians.csv` under `docs/telemetry/experiments/`, lists dominated arms by the experiment's structured rule, and prints `inconclusive` when `n < 3` for an arm or the compared ranges overlap | Given the worked example in runtime.md § Reports Then medians, geometric means and dominance output equal the stated numbers |
| F14 | Run and batch USD ceilings and timeouts come from the experiment file and are enforced by the CLI cap plus a harness check after each turn; an arm model missing from `pricing.json` refuses to start | Given a stub CLI scripted to emit costs Then the run aborts with `budget` at the first turn end at or above the ceiling and `overshoot_usd` is recorded |
| F15 | An experiment file must be committed and unmodified (`git ls-files` tracked, no diff against HEAD) before `exp run` starts; its blob hash is stored in every manifest | Given an uncommitted or modified file Then exit 7 and no run starts |
| F16 | The framework ships a synthetic pilot task with an answer sheet and at least 6 seeded issues, each with an `anchor` string found in the brief or sheet, covering all six categories `collision`, `contradiction`, `missing_limit`, `vague_term`, `wrong_path`, `missing_error` (extra categories are allowed) | Given `tasks/pilot-pinned-note/seeded-issues.json` Then it has 6 or more entries, all six categories, and every anchor is found |
| F17 | Containment: before and after every run the harness hashes the main repo's tracked and untracked tree, `.git/config`, `.git/hooks`, `HEAD` and refs, the harness folder, other runs' folders and `~/.claude/settings.json`; any difference aborts the run as `containment`. The child process gets only the environment allowlist in runtime.md and network tools are denied unless the arm lists them | Given a fake agent that appends to `.git/config` Then the run ends `aborted`, reason `containment`, exit 10 |

## Non-functional
| ID | Category | Requirement | Acceptance criterion |
|---|---|---|---|
| N1 | Accuracy | Extracted arm cost matches the CLI's reported total (sum of `total_cost_usd` over the run's invocations) | At most 2 percent difference on every run that has a reference total; T2 records the field name; T9 fails if fewer than 6 of 9 pilot runs have a reference total |
| N2 | Reproducibility | The manifest holds everything that fixes a run's inputs | `manifest.json` stores base commit, hashes of the arm, task, experiment, answer sheet, rubric, pricing and prompts, harness and CLI versions, model ids, bank snapshot hash at start |
| N3 | Security | No credential pattern (runtime.md table) in any committed file, in artifacts sent to the judge, or in questions shown to the operator | `exp check --secrets` and `exp report` exit 9 on a positive fixture and pass on the negative fixtures (a git sha, a base64 image header) |
| N4 | Isolation | Answerer, matcher and judge run with no tools, a neutral temp directory and no session persistence, and receive only their stated inputs | The prompt builders' unit tests assert no repo path, key or arm id; a launch test asserts the flags |
| N5 | Fairness | `wall_s`, `wait_s`, `answerer_s` and `agent_s` obey `agent_s = wall_s - wait_s - answerer_s` exactly (whole seconds) | A synthetic timeline test with known gaps asserts exact values |
| N6 | Overhead | Model calls outside the arm are costed apart | `runs.csv` has `arm_cost_usd`, `answerer_cost_usd`, `matcher_cost_usd`, `judge_cost_usd`, `probe_cost_usd`; arm cost excludes the other four |
| N7 | Portability | Windows 11 with Node 20 or later, no shell: the CLI is spawned with an argument array, prompts go through stdin; POSIX is best effort | Tests pass on Windows; a launch test passes `& \| ^ " %` inside a question and the child receives it unchanged |
| N8 | Resilience | Crashes leave usable data; extraction is repeatable | `exp extract` run twice gives byte-identical files; a kill during any file write leaves the previous file intact |
