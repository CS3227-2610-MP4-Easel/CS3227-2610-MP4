## Objective

Register the three lead sources safely, add STATIC prompt/schema sections and mock output, and build a
memoized flow that caches only non-degraded rows, calls the gateway outside a transaction, validates
closed suggestions, and writes digest/proposal state atomically.

## Rules that apply

- W6 sources: `lead.facts` is trusted `key=value`, up to 200 rows and 52 chars each, scalar keys in
  `FACT_KEYS` order followed by checkpoints (`targetDate ASC,id ASC`) and overload groups (`userId ASC`);
  `lead.changes` is untrusted, up to 200 rows and 400 chars each, defaults to the last 30 UTC days
  (maximum 31), ordered `at DESC,id DESC`; prior digest is one untrusted `DIGEST` row up to 4000 chars.
  Facts values over 52 chars and prior explanations over 4000 chars are omitted, never truncated.
  No source catches `ContextScopeViolation`.
- W3: literal trusted STATIC sections; injection flags do not block; BLOCKED_INPUT means empty after sanitisation; no output URL/HTML/markdown-link shape.
- Successful admitted session closes `ACCEPTED` after commit; admitted degraded/validation path closes `REJECTED`; pre-admission failure stores null session id.

## Contract

- Source formats: facts use FACT_KEYS order; changes are `<ISO> <type> <task UUID> <from> -> <to>` with null fields empty and controls replaced by spaces; prior explanation is omitted if null or >4000 chars.
- A non-degraded same-hash digest returns cached without a session/call; a degraded same-hash row retries.
- Invalid/foreign/duplicate/conflicting suggestions invalidate the whole result: store degraded digest, no proposal.
- Every persisted digest writes `factsAsOf` from the same captured `Facts.asOf`; latest order is `factsAsOf DESC, createdAt DESC, id DESC` and is executed as one indexed `take: 1` query. Concurrent requests may create rows but no half-write is visible.
- Failure matrix: upstream/timeout/breaker/local-limit after admission stores a degraded row with its
  admitted session `REJECTED`; disabled AI or pre-admission failure stores degraded with null session;
  refusal, blocked input, and schema/output/suggestion failure store degraded with admitted session
  `REJECTED`; only valid output stores a non-degraded row and closes `ACCEPTED` after commit. Every
  degraded row has null explanation/proposal, and `flagged` is true only when the gateway returned it.
