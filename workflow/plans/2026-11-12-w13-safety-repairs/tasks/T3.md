## Objective

Create the protected production workflow with only `push: branches: [main]`, serialized `production` concurrency, `environment: production`, immutable `github.sha` checkout, typecheck/build using only non-secret target identity variables, migration wrapper invocation, and post-migration Deploy Hook request. Vercel performs the final application build with its own protected runtime configuration after the hook. The GitHub workflow must never use Vercel API tokens or direct Prisma commands.

## Rules that apply

- CI receives `DIRECT_DATABASE_URL` and `VERCEL_DEPLOY_HOOK_URL` only through the protected `production` Environment.
- The wrapper command is exactly `node --import tsx scripts/w13/migrate-production.mjs`.
- The Deploy Hook step runs only after successful migration in the same job.
- Vercel Git auto-deploy for `main` must be disabled before this workflow is relied upon; T4 documents the evidence gate.

## Contract

The workflow sets only non-secret build identity variables: `APP_TIER=prod`, `VERCEL_ENV=production`, `NEON_HOST=ep-summer-heart-b3767eul-pooler.c-4.ap-southeast-1.aws.neon.tech`, and `NEON_PROJECT=super-sunset-36592949`. It checks out `${{ github.sha }}`, runs `npm ci --ignore-scripts`, Prisma generate, typecheck, and the frontend build without Firebase, registration, rate, SoCLaaS, or database credentials, then runs the wrapper with protected `DIRECT_DATABASE_URL`. Only after that step succeeds it POSTs the protected `VERCEL_DEPLOY_HOOK_URL`. No `pull_request`, `workflow_dispatch`, `VERCEL_TOKEN`, `VERCEL_TEAM_ID`, or direct Prisma migration appears.
