## Objective
Given a valid plan, one call inserts checkpoints, epics, tasks and `CREATED` events in the caller's transaction, after locking the project row and re-checking project state, actor role and membership. Any invalid plan or state writes nothing and throws. No ids come from the plan.

## Rules that apply
- A-06 - apply functions run in the caller's transaction, validate with a strict schema, ignore any project id in the payload, re-check every id and the actor's role and membership.
- Filtered client has no raw SQL and hides archived projects and soft-deleted rows; `createMany` returns only counts.
- Nested writes - authorise connected ids in the transaction (`checkpointId` comes only from this plan's own generated ids).
- Do not catch errors: the caller's transaction must roll back.

## Contract
`[contract]` `src/be/core/src/plan-input.ts`:
```ts
export const PlanInputSchema = z.object({
  checkpoints: z.array(z.object({ name: z.string().min(1).max(200), targetDate: z.string().regex(/^\d{4}-\d{2}-\d{2}$/) }).strict()).max(8),
  epics: z.array(z.object({ title: z.string().min(1).max(200), description: z.string().max(4000), checkpointName: z.string().max(200).nullable(),
    tasks: z.array(z.object({ title: z.string().min(1).max(200), description: z.string().max(4000),
      acceptanceCriteria: z.array(z.string().min(1).max(300)).max(12), storyPoints: z.union([z.literal(1), z.literal(2), z.literal(3), z.literal(5), z.literal(8), z.literal(13)]) }).strict()).min(1).max(8) }).strict()).min(1).max(10),
}).strict();   // refine: checkpoint names unique ignoring case; each checkpointName is null or equals a checkpoint name exactly; targetDate is a real calendar date
export type PlanInput = z.infer<typeof PlanInputSchema>;
export function countPlan(plan: PlanInput): { checkpoints: number; epics: number; tasks: number };
```
`[contract]` `apply-plan.ts`: `export async function applyPlan(tx: FilteredTransactionClient, projectId: string, plan: unknown, actorId: string): Promise<void>`. Errors thrown: `Error("INVALID_PLAN")` (schema, duplicate or unknown checkpoint names, count mismatch); `Error("CONFLICT_STATE")` (project not ACTIVE); `NotMember` from `@agile/contracts` (actor has no `ProjectMember` row); `Error("FORBIDDEN_ROLE")` (actor's `User.role` is not `PM`).

`[impl]` order inside `applyPlan`: (1) parse `plan` with `PlanInputSchema` -> else INVALID_PLAN; (2) lock the project row: `tx.project.update({ where: { id: projectId }, data: { updatedAt: new Date() } })`; Prisma `P2025` (no active row) -> `Error("CONFLICT_STATE")`; (3) read the actor `User` (role) and `ProjectMember` (projectId, userId); (4) `position` base = `(await tx.epic.aggregate({ where: { projectId }, _max: { position: true } }))._max.position ?? -1` + 1; (5) generate ids with `randomUUID()` for every checkpoint, epic and task; (6) four `createMany` statements in order checkpoints, epics, tasks, task_events. Columns: checkpoint `{id, projectId, name, targetDate: new Date(date + "T00:00:00Z"), version: 1}`; epic `{id, projectId, checkpointId (by exact name, else null), title, description, position: base + index, version: 1}`; task `{id, projectId, epicId, title, description, acceptanceCriteria, storyPoints, createdBy: actorId, version: 1}` (status, blocked take their schema defaults, `sprintId` and `assigneeId` are omitted); event `{taskId, projectId, actorId, type: "CREATED", fromValue: null, toValue: the new task's status name, which is the schema default}`; (7) assert each `createMany` count equals `countPlan(plan)` -> else `Error("INVALID_PLAN")`.
