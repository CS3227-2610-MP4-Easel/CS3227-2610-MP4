## Objective
The PM prompts can receive up to 5 epic and task titles from the caller's member projects, found by keyword match, behind the `PM_SIMILAR_ITEMS` flag.

## Rules that apply
- Filtered client only. `ProjectMember` is scoped to ACTIVE projects, `Epic` and `Task` hide soft-deleted rows; membership removal is a hard delete of the `ProjectMember` row.
- Filter by the caller's member project ids BEFORE searching; W6's membership check is only a backstop. Titles only; at most 5 rows; `ownerId` absent; `ref.type` EPIC or TASK; `projectId` = the item's project.
- A source does not catch `NotMember`; it never throws for an empty result.
- No raw SQL, no typed SQL.

## Contract
`[contract]` `settings.ts`: `export type PmSettings = { similarItems: boolean }; export function loadPmSettings(env: Record<string, string | undefined>): PmSettings` — `PM_SIMILAR_ITEMS` is `"on"` or `"off"`, default `"on"`; any other value throws `Error("INVALID_SETTING:PM_SIMILAR_ITEMS")` (no value in the message).
`[contract]` `similar-items.ts`: `export function createSimilarItemsSource(deps: { db: FilteredDbClient; settings: PmSettings }): ContextSource` and `export function registerSimilarItems(deps): void` (calls `registerContextSource("pm.similarItems", ...)`; a second call throws as W6 does).
Algorithm `[impl]`: flag off -> `[]`. `options.query` (string, may be absent -> `[]`). Keywords = distinct lower-cased matches of `/[\p{L}\p{N}]{4,}/gu` in the query, first 8 in order of appearance; none -> `[]`. Member ids = `db.projectMember.findMany({ where: { userId: caller.userId }, select: { projectId: true } })`; none -> `[]`. `db.epic.findMany` and `db.task.findMany` each: `where: { projectId: { in: ids }, OR: keywords.map((k) => ({ title: { contains: k, mode: "insensitive" } })) }`, `orderBy: { id: "asc" }`, `take: 50`, `select: { id, projectId, title }`. Rank by number of distinct keywords found (case-insensitive) in the FULL title, then EPIC before TASK, then title by code-point order, then id; take 5; row `text` = title cut to 200 characters AFTER ranking.

**Edge cases assigned**
| ID | Scenario | Expected behaviour (exact) |
|---|---|---|
| E12 | member project A and non-member project B hold matching titles | only A's rows are returned |
| E13 | the matching item is soft-deleted; or in an archived project; or the caller's membership row was deleted | not returned |
| E14 | flag `off`; query with no keyword of 4 characters; no match; a Persian query word of 5 letters | `[]` (the first three); the Persian word counts as a keyword |
| E15 | 120 matches, then 12 matches | at most 100 candidates read in id order; exactly 5 returned, ranked by keyword count, then EPIC first, then title by code point, then id; the same input gives the same output twice |
| E16 | a title of 400 characters that matches only because of its last 50 characters | it matches and ranks by the full title; the row text is cut to 200 characters |
| E18 | `PM_SIMILAR_ITEMS=maybe` at startup | `loadPmSettings` throws `INVALID_SETTING:PM_SIMILAR_ITEMS`, without the value |
