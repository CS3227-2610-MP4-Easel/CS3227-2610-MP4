## Objective
The database side of one epic expansion: claim an epic under a lease, store its tasks or a failure, with every race decided by a row lock and a re-read. No model call is made here.

## Rules that apply
- Lock-then-read (Shared context): inside one `db.$transaction`, `update` the proposal row's `updatedAt` by `{ id }` (the lock), re-read, decide; then the epic row the same way.
- Lease 60 000 ms after the claim, longer than the gateway deadline of 25 s. `proposal_epics.version` starts at 1 and rises by 1 on every claim and every store. The proposal's `version` never changes here.
- A late result is discarded, never merged.

## Contract
`[contract]` `expand-store.ts`:
```ts
export const EXPAND_LEASE_MS = 60_000;
export type EpicTask = { title: string; description: string; acceptanceCriteria: string[]; storyPoints: 1 | 2 | 3 | 5 | 8 | 13 };
export type ClaimResult =
  | { kind: "DONE"; epic: PlanEpic }
  | { kind: "CLAIMED"; projectId: string; sessionId: string; approach: string; epic: { title: string; description: string; checkpointName: string | null }; claimedVersion: number };
export async function claimEpic(db: FilteredDbClient, input: { proposalId: string; index: number; actorId: string; now?: Date }): Promise<ClaimResult>;
export async function storeEpic(db: FilteredDbClient, input: { proposalId: string; index: number; claimedVersion: number; tasks: EpicTask[]; flagged: boolean }): Promise<PlanEpic>;
export async function failEpic(db: FilteredDbClient, input: { proposalId: string; index: number; claimedVersion: number; error: string }): Promise<void>;
```
`claimEpic` (one transaction): lock the proposal row; no row, or `createdBy !== actorId`, or `index` not an integer below the epic count -> `ProposalError("NOT_FOUND")`; status not PENDING -> `CONFLICT_STATE`; lock the epic row; by its state: `DONE` -> `{ kind: "DONE", epic }`; `IN_PROGRESS` with `leaseExpiresAt >= now` -> `CONFLICT_STATE`; else (PENDING, FAILED, or lease before now) set `IN_PROGRESS`, `leaseExpiresAt = now + EXPAND_LEASE_MS`, `error` null, `version` + 1, return CLAIMED with `claimedVersion` = the new version and `approach` from the proposal payload.
`storeEpic` (one transaction): lock the proposal row; status not PENDING -> `CONFLICT_STATE` (the epic row is left unchanged); lock the epic row; not `IN_PROGRESS` or `version !== claimedVersion` -> `CONFLICT_STATE`; write `tasks`, `DONE`, `error` null, `leaseExpiresAt` null, `version` + 1; if `flagged`, set the proposal's `flagged` true WITHOUT changing its `version`; return `toPlanEpic(row)`.
`failEpic`: same two guards, but a failed guard returns quietly; on success set `FAILED`, `error`, `leaseExpiresAt` null, `version` + 1.
