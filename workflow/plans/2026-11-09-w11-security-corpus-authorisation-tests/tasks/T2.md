## Objective
Run every validated corpus case through existing guard/gateway/context seams with a literal dispatch
table. Capture logs without exposing fixture text, install network/process/filesystem deny tripwires
before imports, exercise limiter/session barriers, and enforce source-level process safety. The
isolated corpus command runs three successful measurements <=5,000 ms with a hard timeout.

## Rules that apply
- AD-26: no SoCLaaS/network; machine-checkable criteria only.
- AD-25: existing guard reason codes are normative; do not change guard rules.
- W12: runner and corpus are protected; instruction-like strings remain values.
- No dynamic import/eval/Function/child process/shell/network client/repository write.

## Contract
`runner.ts` uses a literal map of validated layer/boundary enums. It captures console and injected
logger sinks and asserts fixture text, tokens, codes, secrets and stack metadata are absent. Setup
loaded with `node --import` before runner/guard/fixture imports blocks fetch, node:http(s), net,
tls, dns, child processes and filesystem writes except temp fixtures. E13 replays a valid code for
the same Firebase identity and expects `409 ALREADY_REGISTERED` with no second row or side effect.
E14 admits exactly limiter cap reservations and every excess is `429 AI_BUSY`; E15 admits exactly
session cap attempts and every excess is `429 RATE_LIMITED`; E22 measures three successful <=5,000 ms runs.
