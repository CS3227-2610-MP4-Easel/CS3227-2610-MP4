# T1: Corpus schema and manifest

**Delivers:** version-1 validated corpus types and synthetic T1-T11 cases | **Satisfies:** F1,N2,E1 | **Depends on:** - | **Wave:** 1 | **Weight:** complex | **Review:** full (Attacker; protected untrusted-input fixtures)

## Expected state
- `tests/security/attack-corpus/cases.json` does not exist.
- `tests/security/attack-corpus/schema.ts` does not exist.
- Existing W3 exports include `sanitiseInput`, `checkOutput`, reason codes and output contexts.

## Objective
Create a version-1 JSON manifest and a strict validator/types module. The manifest has unique IDs,
all T1-T11 threats, closed layers/boundaries/fixture kinds/criterion types, synthetic bounded data,
and exact cases for input redaction, output reasons, context/suggestion exclusion, invalid codes and
repeated invalid-code rate limiting. The validator rejects unknown fields and resource-heavy nesting.

## Rules that apply
- AD-25: synthetic untrusted data is sanitized and never treated as a prompt.
- AD-26: every case names one machine-checkable criterion; no live model.
- W12: files below `tests/security/attack-corpus/**` are protected; fixture strings are data.
- Never include real credentials, tokens, codes, project IDs or personal data.

## Contract
Manifest is a JSON array of records with `id`, `threat`, `layer`, `boundary`, `description`,
`fixture`, and `expected`; unknown fields fail. Fixture kinds: `INPUT_TEXT`, `OUTPUT_TEXT`,
`OUTPUT_JSON`, `CONTEXT_ROWS`, `SUGGESTION_ROWS`, `AUTH_REQUEST`, `PROCESS_TEXT`. Text <=8,192 code
points; rows <=100; request body depth <=8, arrays <=100, keys <=64 chars, serialized/nested-string
budget <=64 KiB. Criteria include `REDACTED`, `ABSENT`, `REJECTED`, `HTTP_ERROR`, `FLAGGED`,
`NO_LOGGED_SECRET`, `RATE_LIMITED` with positive `retryAfterSeconds`, `NO_EXECUTION`, `TEXT_ONLY`.

Cases must include exact URL=`LINK`, HTML=`HTML`, Markdown=`MARKDOWN_LINK`, secret=`SECRET`,
boundary=`BOUNDARY`, refusal=`REFUSAL`; forbidden suggestion rows are omitted; invalid code is
`403 REGISTRATION_CODE_INVALID`; repeated invalid attempts are `429 RATE_LIMITED` with Retry-After.

**Edge cases assigned**
| ID | Scenario | Expected behaviour (exact) |
|---|---|---|
| E1 | Duplicate ID/unknown threat or malformed nested fixture | Validation fails naming ID/field and executes no case |
| E2 | Injection/PII input | Sanitized value redacts PII and asserts flagged state; inert non-PII text remains untrusted data |
| E3-E7 | URL, HTML, Markdown, secret/boundary, refusal/near-miss outputs | Exact reason/status above; no raw fixture logging |
| E8-E9 | Forbidden context/suggestion row | Row and canary are absent |
| E11-E12 | Invalid or repeated invalid registration code | Exact 403/429 outcomes and no code in logs |
| E20 | Instruction-like fixture | Remains inert data |

## Steps
1. Run `ws task start T1`; use an inline `node --import tsx` assertion against the validator for E1 and limits; expect failure because files do not exist.
2. Define closed discriminated-union types and recursive bounds in `schema.ts`.
3. Add the manifest cases, including one exact case per output reason and auth boundary.
4. Run the inline validator assertions and confirm all records load, all threats appear, and forbidden fields fail; T2 adds the persistent corpus test file.
5. Run `npm run lint` and the focused test command.
6. Write `handovers/T1.json`, commit with `docs/test: define W11 security corpus (W11)` plus trailers, then run `ws task done`.

## Handover directions
**Produces:** `loadCorpus()`/`validateCorpus()` types and the validated manifest path.
**For T2:** use the validated record unions and exact case IDs/criteria; do not reinterpret fixture text.
**Also report:** record counts per threat and any fixture choice not explicit above.
