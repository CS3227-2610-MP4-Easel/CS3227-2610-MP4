**Delivers:** complete policy-derived authorization matrix and route-handler source rule | **Satisfies:** F5,F6,N3,E10,E16,E17,E18,E19,E20,E23 | **Depends on:** - | **Wave:** 1 | **Weight:** complex | **Review:** full (Attacker; roles, tenancy and protected API tests)

## Expected state
- `src/be/contracts/src/policy.ts` exports `getPolicyMap()` with 57 entries and `PolicyEntry` fields.
- `src/be/api/src/middleware/auth.ts` exports `authorizeRequest` and existing fakes support resolver, membership and predicate seams.
- `src/be/api/test/authorization-generated.test.ts` and `authorization-source-rules.test.ts` do not exist.

## Objective
Derive rows at test time from `getPolicyMap()` and prove completeness, exact auth-state outcomes,
role allows/denials, predicate allows/denials, hidden cross-project behavior, archived precedence,
zero parser/predicate/handler calls after denial, and no direct role authorization in route handlers.

## Rules that apply
- AD-55: policy map is the only route authorization source; handlers pass identity to domain services.
- AD-26: generated authorization tests are independently reviewed from guard authors.
- Hidden/cross-project resources are `404 NOT_FOUND`; archived member writes are `409 CONFLICT_STATE`.
- Synthetic role `AUDITOR` is disjoint from PM/DEV_LEAD/DEVELOPER and must produce `403 FORBIDDEN_ROLE` on restricted policies.

## Contract
Assert 57 unique policy keys/operation IDs. For each policy create `AUTH_REQUIRED`; restricted roles
get one `ROLE_ALLOW` per declared role and one `ROLE_DENY` with `AUDITOR`; non-`NONE` predicates get
one `PREDICATE_ALLOW` and one `PREDICATE_DENY`; unrestricted policies get a synthetic PM allow.
`PUBLIC` missing token continues; TOKEN/REGISTERED missing token is `401 UNAUTHENTICATED` and a
verified token without a user is `403 USER_NOT_REGISTERED`; role denial is `403 FORBIDDEN_ROLE`;
hidden/cross-project is `404 NOT_FOUND`; archived member write is `409 CONFLICT_STATE`.
Predicate factories use `ResolvedResource { kind, projectId, state, ownerId?, assigneeId?, developerId?, targetRole? }`:
MEMBER has caller/resource project equality for allow and mismatch for deny; MEMBER_PROJECTS supplies
the caller's member-project set; SELF sets `developerId`/owner to caller versus another user;
MEMBER_OR_ASSIGNEE uses member=true or assigneeId=caller; ADDER first resolves active project and
membership before body parsing, then `authorizeAdder` receives the parsed target role. Every denial
asserts zero body-parser, predicate-after-failure and handler calls.
