## Scope
**Goal:** a Firebase account becomes a platform user only with its role's registration code, every protected request is tied to a verified identity and a stored role, and other modules get a shared atomic rate limiter.
**In scope:** F1 to F6, N1 to N7; endpoints 2 (`check-code`), 3 (`register`) and 4 (`me`); `resolvePrincipal`, `lookupRegisteredUser`, `hit`; the two optional route seams (SD13).
**Non-goals:** the sign-in screen (T7, F7 and its UI edge cases, moved to [follow-up-t7.md](../specs/2026-10-31-w4-auth-design/follow-up-t7.md) by SD18); `requireMember` and the membership resolvers (W5, SD9, SD15); email verification and revocation (guardrails **Email verification and disabling users**, AD-57); `rate_counters` cleanup (Known Gap, SD10); schema changes (W1).
**Risk tier:** High. Every task is test-first; the integration tests (E8, E10, E22, E23, E25, E26, E35, E41) must be run against a real Postgres 16, not left skipped; the branch gets the Attacker and Tester review lenses before Gate 3.

**Commands** (from `STATE.md` §2): `<TEST>` = `npm test`; one area = `node --import tsx --import ./tests/setup-auth-env.ts --test <files>` (the setup import exists from T3 on; before that, omit it). `<BUILD>` = `npm run typecheck`, then `npm run lint`, then `npm --workspace @agile/db run prisma:validate`.

**Integration database:** integration tests reuse W1's switch, `W1_INTEGRATION_DATABASE_URL`, and skip without it. To run them: `docker run --rm -d --name w4-pg -p 5433:5432 -e POSTGRES_PASSWORD=pg postgres:16`, then `DATABASE_URL=postgresql://postgres:pg@localhost:5433/postgres npx prisma migrate deploy --schema src/be/db/prisma/schema.prisma`, then set `W1_INTEGRATION_DATABASE_URL=postgresql://postgres:pg@localhost:5433/postgres?connection_limit=25` (pool of at least 21, conventions § Tests).

**Naming note:** the spec's 500 `INTERNAL` is the contracts code `INTERNAL_ERROR` produced by W1's `errorResponse` (`src/be/api/src/errors.ts`); contracts are normative (C20). Tests assert `INTERNAL_ERROR`.

The statement (AD-59, one atomic upsert on the database clock; `now()` is fixed for the statement). `window_start` is `TIMESTAMP(3)` without a time zone and Prisma stores UTC, so every `now()` is taken as UTC:
```sql
INSERT INTO rate_counters (key, window_start, count) VALUES (${key}, (now() AT TIME ZONE 'UTC'), 1)
ON CONFLICT (key) DO UPDATE SET
  count = CASE WHEN (now() AT TIME ZONE 'UTC') >= rate_counters.window_start + make_interval(secs => ${windowSeconds}::double precision) THEN 1 ELSE rate_counters.count + 1 END,
  window_start = CASE WHEN (now() AT TIME ZONE 'UTC') >= rate_counters.window_start + make_interval(secs => ${windowSeconds}::double precision) THEN (now() AT TIME ZONE 'UTC') ELSE rate_counters.window_start END
RETURNING count, CEIL(EXTRACT(EPOCH FROM (window_start + make_interval(secs => ${windowSeconds}::double precision) - (now() AT TIME ZONE 'UTC'))))::int AS remaining_seconds
```
`ON CONFLICT` locks the row, so concurrent calls serialise (E8); the `SET` expressions read the old row and `RETURNING` reads the new one. Run it with `client.$queryRaw` (tagged template, so values are parameters) and read `rows[0]`, since `$queryRaw` returns an array. `createHit`: `allowed = count <= limit`; when allowed `retryAfterSeconds = 0`, else `min(max(remainingSeconds, 1), windowSeconds)`; the cap exists because millisecond rounding can make `remainingSeconds` one more than `windowSeconds`. Arguments are checked first and throw `RangeError` without calling the counter: `key` 1 to 200 characters; `windowSeconds` and `limit` positive integers.

`clientIpKey(purpose, forwardedFor, secret)`: take the first comma-separated value of `forwardedFor`, trimmed; if `net.isIP` is 0, use `unknown`; unwrap `::ffff:a.b.c.d` (and its hex form) to IPv4; reduce IPv6 to the first four groups, expanded and lowercased, joined with `:`, plus `::/64`; return `ip:` plus hex HMAC-SHA256 keyed by `secret` over `<purpose>:<normalised ip>`.

`resolvePrincipal(authorization)`: reject before calling the verifier unless the header matches `/^Bearer +(\S+)$/i` and the token is at most 4096 bytes (`Buffer.byteLength`); two headers arrive joined as `"Bearer a, Bearer b"` and fail the pattern (E1). Map `InvalidToken` and a null email to `Error("UNAUTHENTICATED")`; rethrow `VerifierUnavailable` (W1 turns it into 500). Return `{ firebaseUid: uid, tokenClaims: { email: email.toLowerCase() } }`.

`lookupRegisteredUser(firebaseUid)`: `db.user.findUnique({ where: { firebaseUid }, select: { id: true, role: true } })`; no row -> `Error("USER_NOT_REGISTERED")`; return `{ firebaseUid, userId: id, role }`.

Firebase adapter default:
```ts
const app = getApps().find((a) => a.name === "w4-auth") ?? initializeApp({ projectId }, "w4-auth");
try { const d = await getAuth(app).verifyIdToken(token, false); return { uid: d.uid, email: typeof d.email === "string" && d.email !== "" ? d.email : null }; }
catch (e) { const code = (e as { code?: unknown }).code; if (typeof code === "string" && code.startsWith("auth/") && code !== "auth/internal-error") throw new InvalidToken(); throw new VerifierUnavailable(); }
```

Runtime (`runtime.ts`): `createAuthRuntime(env, overrides?: { verifier?: TokenVerifier; base?: PrismaClient })` calls `loadAuthSettings(env)` (throws on bad settings), creates one `PrismaClient` lazily (no connection until first query), passes it to `createDbClient`, and builds `hit` as `createHit((k, w) => incrementRateCounter(base, k, w))`, and returns `{ settings, hit, resolvePrincipal, lookupRegisteredUser, db }`. When `settings.firebaseProjectId` is null (E50), `resolvePrincipal` and `lookupRegisteredUser` throw `Error("AUTH_NOT_CONFIGURED")`, which W1 maps to 500. `getAuthRuntime()` creates it once from `process.env` and caches it.

`createAppDependencies(auth: Pick<AuthRuntime, "resolvePrincipal" | "lookupRegisteredUser">)` returns those two functions, plus fail-closed placeholders until W5 replaces them (SD15): `resolveResource: async () => null` and `requireMember: async () => { throw new Error("NOT_FOUND"); }`, with `evaluatePredicate: createPredicateEvaluator(requireMember)`.

`limitedBefore(purpose)` (spec `api.md` pipeline step 2, `conventions.md` § Rate-limit keys):
1. If `runtime().settings.rateKeySecret` is null, return a 500 `INTERNAL_ERROR` response (E50).
2. Read `x-vercel-forwarded-for`; if it gives `unknown` on tier `dev` or `prod`, `console.warn("client_ip_missing")` (E49).
3. `hit(clientIpKey(purpose, header, secret), 60, 20)`; when not allowed, return `errorResponse(new HttpError("RATE_LIMITED", 429, "Too many attempts."), requestId)` with `Retry-After` set to `retryAfterSeconds`.
4. If `Content-Length` is a non-negative integer over 4096, return 413 `PAYLOAD_TOO_LARGE`. Otherwise (absent, invalid or within the limit), read `request.clone().body` with a reader, counting bytes, and cancel and return 413 as soon as the count passes 4096, so an oversized body is never fully buffered.

`CheckCodeBodySchema` is defined in `auth.ts`, because the contracts' `UserInputSchema` is looser than the spec. W1's `parseInput` copies each zod `issue.message` into `details` (`src/be/api/src/errors.ts:18`), and zod's default messages quote submitted values (`received 'ADMIN'`, `Unrecognized key(s) in object: 'x'`). So every field and the object carry fixed messages (E17, E25):
```ts
const fixed = (message: string) => ({ errorMap: () => ({ message }) });
const RoleField = z.enum(["PM", "DEV_LEAD", "DEVELOPER"], fixed("Must be PM, DEV_LEAD or DEVELOPER."));
const CodeField = z.string(fixed("Must be 1 to 128 characters.")).min(1).max(128);
export const CheckCodeBodySchema = z.object({ role: RoleField, code: CodeField }, fixed("Invalid request body.")).strict("Unknown field.");
``` The handler returns 403 `REGISTRATION_CODE_INVALID` on a wrong pair, else 200 `{ valid: true }`. No CORS middleware is added.
