- T1 handover reports the core factory and membership/error APIs.
- `src/be/contracts/src/schemas.ts` exports project, member, and checkpoint schemas.
- `src/be/api/src/routes/index.ts` currently registers only health/auth routes.

## Objective
Implement storage-scoped project creation/list/detail/member and checkpoint behavior in core plus HTTP route definitions that only translate validated input and domain results.

## Rules that apply
- F3/F4 — email is trimmed/lowercased before injected lookup; PM adds only DEV_LEAD and DEV_LEAD only DEVELOPER.
- N2 — creator membership, add-member race handling, and checkpoint creation use one mutation transaction.
- E7/E34 — members see archived writes as 409 only after internal membership proof; non-members receive 404.

## Contract
Project creation creates ACTIVE project plus creator membership. Project lists page newest-first; checkpoints order by target date/id. Repeated add-member returns 200 existing member; invalid/missing target returns 422 with no write. Core route service methods receive `{ userId, role }` and reject absent/mismatched actors with `FORBIDDEN_ROLE`. Export `createProjectsRoutes(services)` and `createCheckpointsRoutes(services)` factories; handlers use only their injected narrow service, never a DB client. T5 supplies ADDER's post-parse target-role phase.
