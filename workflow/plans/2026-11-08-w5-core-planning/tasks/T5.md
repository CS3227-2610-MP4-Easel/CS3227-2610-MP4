## Contract
`createAppDependencies` supplies `resolveResource` and `requireMember` from core, then predicates use those same functions. API composition constructs core with `AuthRuntime.lookupUserByEmail(email)` and `lookupUserRole(userId)`—new auth-owned filtered-client functions, never API table queries—then calls `registerCore(core)`, registers W5 sources, and invokes the T2/T3 route factories with narrow service objects.

For `ADDER`, authorization is two phase: before body parsing resolve project/archive/membership and preserve malformed-path and archived 404/409 precedence; after valid body parsing, normalize email, obtain the storage target role, and evaluate ADDER before the handler. A malformed/archived path never parses its body.
