**Delivers:** progress/velocity, strict applyPlan/applyReplan, and four W5 context sources | **Satisfies:** F1, F7, F8, N1, N4, E19, E20, E22, E24, E25, E31, E32, E33, E36, E38 | **Depends on:** T1, T3 | **Wave:** 4 | **Weight:** complex | **Review:** full (transaction and source-scope boundary)

## Expected state
- T1 factory/resolvers and T3 task/event service helpers exist.
- `src/be/ai-context/src/registry.ts` exposes `registerCore` and `registerContextSource`.
- No production core module imports `@agile/ai-context`.

## Objective
Finish the frozen Core methods and add a composition-callable source-registration function without coupling core to ai-context. Validate apply payloads before mutation and use the supplied transaction for every resulting row/event.

## Rules that apply
- F8 — ignore embedded project ids; recheck actor role, membership, writability, every target, and assignee.
- N4 — derive progress/velocity from one filtered-client snapshot; zero total points yields zero percent.
- SD5 — exactly four W5 source ids, storage-derived fields, fixed ordering/caps, and no text truncation.

## Contract
`progress` returns `{ pointsTotal, pointsDone, percent, unestimatedTasks }`; `velocity` accepts 1..100 or throws `RangeError("INVALID_VELOCITY_LIMIT")`. Apply operations throw VALIDATION_FAILED, FORBIDDEN_ROLE, or CONFLICT_STATE and leave no partial rows/events. Sources omit over-limit rendered rows and fail as `CORE_SOURCE_FAILED:<sourceId>`.
