# T3: Epics and task lifecycle

**Delivers:** epics and tasks services/routes with events, relation validation, optimistic concurrency | **Satisfies:** F5, F6, N1, N2, E8, E9, E10, E11, E12, E13, E14, E15, E16, E17, E26, E28, E29, E30, E37 | **Depends on:** T1, T2 | **Wave:** 3 | **Weight:** complex | **Review:** full (mutable shared data and authorization)

## Expected state
- T1 core factory and T2 project-scoped mutation helpers exist.
- Prisma schema already contains Epic, Task, TaskEvent, Sprint, and composite relations.
- The frozen task event enum is unchanged.

## Objective
Implement endpoints 16-17 and 20-24 through core-owned services, including live aggregates, strict inputs, project-safe relationships, version compare-and-increment, and atomic task-event writes.

## Rules that apply
- SD6 — do not add task-event enum values; only the specified event-bearing fields emit events.
- N2 — all row/event work is one RepeatableRead transaction; status event precedes block event.
- E14 — any mutation on a CLOSED sprint fails 409 with no state/event change.

## Contract
Epic creation serializes next position by locking the project row. Task create writes CREATED. PATCH rejects status/block fields and emits only points, assignee, and sprint changes in that field order. Status sets/clears `doneAt`; a no-op does not increment version or emit events. Direct calls require matching actor role. Export a `createPlanningRoutes(services)` factory so handlers close over narrow core services.

**Edge cases assigned**
| ID | Scenario | Expected behaviour (exact) |
|---|---|---|
| E8-E10 | cross-project relations or sprint without points | 422 and no write |
| E11-E13 | block/status handling | exact reason, doneAt, and event semantics |
| E14-E16 | closed sprint/stale/no-op | 409 or no version/event change |
| E17, E29-E30 | deleted or forbidden filter/relations | hidden/422 as specified |
| E26, E28, E37 | event failure/racing epics/direct call | rollback, unique positions, forbidden actor |

## Steps
1. Run `ws task start T3`; write failing core/API tests for every listed edge case.
2. Build epic listing/creation with filtered counts and serialized positions.
3. Build task reads, create, patch, and status transitions with strict validation and relation checks.
4. Add task-event writer and atomic optimistic-version behavior; prove rollback on an injected event failure.
5. Add the service-injected route factory and run targeted tests, typecheck, lint, and Prisma validation.
6. Write `handovers/T3.json`, commit with trailers, then run `ws task done`.
