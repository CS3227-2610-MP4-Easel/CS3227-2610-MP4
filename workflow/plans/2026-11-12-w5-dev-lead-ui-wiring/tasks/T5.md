# T5: focused verification and closeout repairs

**Delivers:** Green W5 frontend verification and a review-ready branch. **Satisfies:** F8,N1,N2,N3,E8,E10.
**Depends on:** T3,T4 **Wave:** 3 **Weight:** complex **Review:** full

## Expected state
- T3 and T4 handovers and commits are present.
- All live W5 screens and route/error seams are implemented.

## Objective
Run the requirement-labelled frontend suite, typecheck and lint. Confirm no direct database imports, live
prototype fallback, forbidden dialogs or sprintId writes. If a check fails, return `blocked` with the
requirement ID and exact failing path for the owning task; do not make unplanned cross-task repairs.

## Rules that apply
- N3 Every F/N/E requirement has a named passing test or recorded manual check.
- Verification must not weaken tenancy, role or safe-error behavior to make tests pass.

## Contract
The closeout is green only when frontend tests, typecheck and lint pass and the route, error, source,
tenancy and no-sprintId checks are present.

## Files
| Action | Path | What changes |
|---|---|---|
| Test | `src/fe/test/w5-closeout.test.ts` | F1-F8,N1-N3,E1-E15 verification matrix |

## Steps
1. Create the verification matrix in `w5-closeout.test.ts`, naming every F/N/E ID.
2. Run frontend tests, typecheck and lint; record failures by requirement ID.
3. Re-run frontend and root verification commands.
4. Review the diff for data-source, tenancy, role and mutation regressions.
5. Write `handovers/T5.json`, update branch state to In review, and commit with `Task: T5`.

## Handover directions
**Produces:** final evidence, clean branch state and a review-ready W5 branch. **For the orchestrator:**
use the evidence for Gate 3 and do not claim completion without green commands.
