## Objective
Two store functions, each in one transaction, that change a PENDING proposal's checkpoints or one epic and return the fresh `PlanProposal` view. Every edit is creator-only, version-guarded, serialised by the proposal lock, validated as a whole plan before commit, and marks the proposal edited.

## Rules that apply
- Check order inside the transaction: `lockProposal` (null: NOT_FOUND); proposal not created by `actorId`: NOT_FOUND; `status !== "PENDING"`: CONFLICT_STATE; `version !== input.version`: CONFLICT_VERSION; then body rules (VALIDATION_FAILED).
- Liveness of an epic: `status === "IN_PROGRESS" && leaseExpiresAt !== null && leaseExpiresAt.getTime() >= now.getTime()` (the same comparison as `claimEpic`); `now` is `input.now ?? new Date()`.
- Epic `version` +1 when a write sets `tasks`, changes title or description to a different value, or changes the expansion status; a write that sets `tasks` also sets `leaseExpiresAt: null`, `error: null`, status `DONE`. A checkpoint-name-only change leaves epic `version` and lease untouched. Any edit recomputes `contentHash` with `epicContentHash(title, description, checkpointName)`.
- Proposal: `version` +1 and `payload.edited = true` on every successful edit, merging into the existing payload (`approach`, `retrieved`, `applied` survive).
- Before commit, validate the resulting plan with `PlanInputSchema.safeParse({ checkpoints, epics })` where each epic's `tasks` is its stored tasks if DONE or one placeholder task `{ title: "x", description: "", acceptanceCriteria: [], storyPoints: 1 }` otherwise; on failure throw `ProposalError("VALIDATION_FAILED", field)`.
- Name matching is exact and untrimmed; checkpoint-name uniqueness is case-insensitive (PlanInputSchema).

After the transaction commits, both functions return `getProposalView(db, proposalId, actorId)`; a `null` view throws `ProposalError("NOT_FOUND")`. The returned `version` may already include a later concurrent edit; that is acceptable.
`editEpic`: the index is checked after `guardEdit` (so a stale version beats an unknown index; this differs from endpoint 37 on purpose): not an integer in `0..count-1`: NOT_FOUND. `checkpointName` (when not undefined) must be null or equal a name in `payload.checkpoints`, else VALIDATION_FAILED("checkpointName"). Epic live: CONFLICT_STATE. Title or description sent equal to the stored value counts as unchanged. With `tasks` absent, status, tasks and error stay as they are.
`replaceCheckpoints`: names unique ignoring case, `targetDate` a real calendar date, `previousName` equal to a current name exactly and used at most once (else VALIDATION_FAILED); stored entries are `{name, targetDate}` only. Each epic's `checkpointName` becomes the `name` of the entry whose `previousName` equals it; else itself if some entry has exactly that name; else null (simultaneous mapping from the old names). Lock every epic row in ascending index order; a live epic does not block; only `checkpointName` and `contentHash` change.
