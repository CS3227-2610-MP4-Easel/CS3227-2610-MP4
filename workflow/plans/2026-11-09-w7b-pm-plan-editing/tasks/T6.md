## Objective
`listProposals` returns `{ items, page, size, total }` for one project's PLAN proposals, newest first, with `retrieved` resolved per viewer exactly as `getProposalView`, in at most 8 database queries per page. `getProposalView` behaviour does not change.

## Rules that apply
- Member PMs see every PLAN proposal of the project; a REPLAN proposal is neither listed nor counted.
- Order: `createdAt` descending, then `id` descending.
- Share the `retrieved` and epic mapping with `getProposalView` (extract one builder; do not copy it).
- `toPlanEpic` and `getProposalView` keep their names, signatures and exports at every commit (another task in this wave imports them).

## Contract
```ts
// view.ts [contract]
export async function listProposals(db: FilteredDbClient, i: { projectId: string; viewerId: string; status?: "PENDING" | "APPROVED" | "REJECTED" | "SUPERSEDED"; page: number; size: number }): Promise<{ items: PlanProposal[]; page: number; size: number; total: number } | null>;
```
Returns `null` when the viewer is not a member of `projectId` (the route turns it into 404). Query order (8 queries at most): (1) `projectMember.findFirst({ userId: viewerId, projectId })`; null returns `null` before anything else; (2) `count` with the filter `{ projectId, kind: "PLAN", status? }`; (3) `findMany` for the page with the same filter (`kind: "PLAN"` is in both), `orderBy` createdAt desc then id desc, `skip: page*size`, `take: size`; (4) one `proposalEpic.findMany` with `proposalId in (...)`; (5) one `projectMember.findMany({ userId: viewerId, projectId in union(projectId, every retrieved project of the page) })`; (6) `project.findMany` for names; (7) `epic.findMany` and (8) `task.findMany` for retrieved titles (each skipped when empty). A page past the end returns `items: []` with the real `total`. The shared builder maps epics with `toPlanEpic(row, now)` using one `now` for the whole page.
