## Objective
The flow exposes the six new operations. Edits pass through to the stores and map errors; `regenerateEpic` runs the sequence precheck, session checks, claim, one model call, store; `listProposals` maps the page. The runtime binds the real functions. No model call inside a transaction; exactly one `run` call for a regeneration that reaches the model, none otherwise.

## Rules that apply
- `plan-flow.ts` mirrors the store types (no import from `@agile/proposals`); recognise `ProposalError` by name as today.
- Extend the mirrored `ProposalErrorLike` with the code `VALIDATION_FAILED` and `field?: string`. `mapProposalError` gains `VALIDATION_FAILED`: `PlanFlowError("VALIDATION_FAILED", 422, "The request could not be used.", undefined, { reason: e.field ?? "invalid" })` (the route's `respond` already turns `details` into `[{ field: "reason", message }]`).
- Clock: pass `now: clock.now()` to `editEpic`, `deleteEpic`, `precheckRegenerate` and `claimEpic`, and add `now?: Date` to those `ProposalsApi` input types, so liveness uses the flow's injected clock.
- Regenerate sequence: (1) `proposals.precheckRegenerate({ proposalId, index, actorId, version, now })` (errors via `mapProposalError`). (2) If `status === "DONE"`: `sessions.assertUsable(sessionId, userId, "PM_PLAN_EXPAND")` first (kept so a closed or idle session is 409 "The AI session expired; start a new plan." via `mapThrown`, never the false 429 that `regenerate` would give), then `sessions.regenerate(sessionId, userId)`; `SessionCapReached` gives `PlanFlowError("RATE_LIMITED", 429, "Regeneration limit reached.", e.retryAfterSeconds)`. (3) `claimEpic({ ..., now, mode: status === "DONE" ? "REGENERATE" : "EXPAND", expectedProposalVersion: status === "DONE" ? version : undefined })`; a lost race answers 409 and the cap stays spent. (4) Run the model and store exactly as `expandEpic` does, passing `bumpProposalVersion: true` only when `status === "DONE"`. (5) Return `getProposalView` of the proposal.
- Failure path (also for `expandEpic`): when the model fails, call `failEpic`; if it returns `false` (the epic moved under the old call), throw `PlanFlowError("CONFLICT_STATE", 409, "The proposal or project is no longer in a state that allows this.")` instead of the mapped model error; otherwise throw the mapped model error as today.
- Refactor `expandEpic`'s body that follows a `CLAIMED` result into one internal function used by both.
