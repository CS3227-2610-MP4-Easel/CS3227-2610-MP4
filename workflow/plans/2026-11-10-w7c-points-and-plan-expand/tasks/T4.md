## Contract
```ts
// sections.ts [contract]
export type PlanTargetEpic = { index: number; title: string; description: string; checkpointName: string | null };
export type PlanContextEpic = PlanTargetEpic & { tasks: { title: string; acceptanceCriteria: string[]; storyPoints: number }[] | null };
export const PM_PROMPT = { outline: { rules: 600, outputFormat: 500, today: 30, idea: 1750 },
  expand: { rules: 600, outputFormat: 500, approach: 400, epic: 600, otherEpics: 2600 },
  bulk: { rules: 600, outputFormat: 500, approach: 400, epics: 1400, doneEpics: 1800 } } as const;
export function bulkStaticSections(): LlmCall["sections"];
export function buildBulkSections(i: { approach: string; targets: PlanTargetEpic[]; done: PlanContextEpic[]; assembled: ContextSections }): ContextSections;
export function buildExpandSections(i: { approach: string; epic: { title: string; description: string }; others?: PlanContextEpic[]; assembled: ContextSections }): ContextSections;
export function bulkQuery(targets: PlanTargetEpic[]): string;   // flattened target titles joined by one space, cut to 1000 code points; never empty: when the result would be empty return "epics" (the context option `query` must have at least 1 character)
// schemas.ts [contract]
export function bulkOutputSchema(targetIndexes: number[]): ZodTypeAny; // { epics: [{ index, tasks: Task[1..8] }] }, exactly the target indexes, each once, any order
```
**Section order.** Bulk: `rules`, `output-format`, the assembled sections, `approach`, `epics`, `done-epics` (omitted when `done` is empty). Single: `rules`, `output-format`, assembled, `approach`, `epic`, `other-epics` (omitted when `others` is empty).
**Field rules, every interpolated text:** line breaks, carriage returns and tabs become one space; runs of spaces collapse; epic title cut to 120 code points, description to 200, checkpoint name to 80; task title to 100 (60 at level 0); a criterion to 100. A target block is `index: N`, `title: T`, `description: D`, `checkpoint: C or none`, blocks separated by one blank line. **Trim levels** (one renderer for `done-epics` and `other-epics`, first level whose wrapped text, `estimateTokens(wrapSection(name, text, PLACEHOLDER_BOUNDARY), FEATURES.PM_PLAN_EXPAND.model)`, fits the section budget): level 2 = the block plus `tasks:` and per task `- title (P points): criterion; criterion` (at most 2 criteria); level 1 = per task `- title (P points)`; level 0 = `index:` and `title:` only plus per task `- title (P points)`; an epic without tasks prints `tasks: none`. Level 0 of nine epics of eight tasks is about 1,500 to 1,700 tokens, inside both budgets (1,800 and 2,600); if the E24 test shows level 0 does not fit, stop and report `blocked` rather than cutting task lines.
**Types.** `PlanTargetEpic` and `PlanContextEpic` are exported from `sections.ts` only (`pm/src/index.ts` re-exports both `sections.js` and `plan-flow.js`, so T6 must not declare them again).
**Texts** [contract]. Every `output-format` begins "Answer with one JSON object and no other text: no markdown fences, no comments, no trailing commas." (outline and single keep their shapes). Bulk `rules`, lines joined by newline: "Task: write the tasks of every epic in the epics section in one pass, so the whole plan flows logically." / "Work through the epics in order. An epic may build on the tasks of earlier epics. Never repeat work that another epic already covers: each piece of work is a task in exactly one epic. Epics in the done-epics section are already written: do not repeat or change them." / "Limits: 3 to 6 tasks per epic; titles up to 200 characters, descriptions up to 1000; 1 to 4 acceptance criteria per task, each up to 300 characters." / "Story points are whole numbers from 1 to 20 that estimate effort; use small numbers for small tasks. Do not invent dates." plus the three common rules. Bulk `output-format` adds: `{"epics": [{"index": number, "tasks": [{"title": string, "description": string, "acceptanceCriteria": [string], "storyPoints": number}]}]}`, "Include one entry for every epic in the epics section, in the same order, with its index." and "Every task has all four fields. storyPoints is a whole number from 1 to 20 on every task, never missing and never null." Single `rules`: the points line becomes "Story points are whole numbers from 1 to 20 that estimate effort. Do not invent dates." and gains "The other-epics section lists the rest of the plan: do not repeat its tasks, and make these tasks fit with them."
**Mock** [contract]: `registerMockResponse("PM_PLAN_EXPAND", (call) => ...)` (it receives the original `call.sections`, not the wrapped prompt): if the call has a section named `epics`, return `{"epics":[...]}` with one entry per line matching `^index: (\d+)$` in that section, each with three tasks (points 3, 5, 2); otherwise today's answer.
