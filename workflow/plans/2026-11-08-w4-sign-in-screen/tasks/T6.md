## Objective
New users pick a role, enter the code, then create their Firebase account and profile; a Firebase account without a profile finishes setup without creating a second account. The code never leaves component state.

## Rules that apply
- SD3 - never navigate to `/projects`; `setUser` makes the session `ready` and the gate replaces the route.
- SD4 - one component, steps in state, URL stays `/register`.
- SD10 - call `holdForRegistration()` right before `signUp`; release after `setUser`, or when the chain ends in an error.
- SD11 - once `signUp` has succeeded in this component instance, a later Create account or Retry skips `signUp` and repeats only `register_3`. The code is cleared (state and input value) on `register_3` success, on 409 and on unmount; on every other error it is kept.
- The code is never written to storage, a URL, a log or an error message. Display names render as React text.
- If the component unmounts after `signUp` succeeded but before `setUser`, it calls `session?.retry()` in the unmount cleanup, so the session re-reads `/api/me` (403 -> `unregistered`) and the next visit shows finish setup instead of a stale `signed-out`.
- `useSession()` is typed nullable; read it with `?.`.
- One request at a time: a `useRef` guard plus `disabled`; in flight -> `aria-busy="true"` and label "Please wait…".

## Contract
`components/live/register.tsx` [contract] (`'use client'`, default export `Register()`). Copy markup and classes from the three canvases; inputs controlled and empty; links become buttons or `<a>` as below.
- **Step 1 "Role and code"** (`Register.tsx`): radio group of three cards, Project Manager (`PM`), Dev Lead (`DEV_LEAD`), Developer (`DEVELOPER`), none preselected, each a real `<input type="radio" name="role">` with its label; Registration code `<input type="password" autoComplete="off">`; Next disabled until a role is chosen; Next -> `checkCode_2(role, code)`; success -> step 2. "Back to sign in" is `<a href="/sign-in">`.
- **Step 2 "Account"** (`RegisterAccount.tsx`): chip "Role: <label>, code accepted"; Display name; Email (`type="email"`, `autoComplete="email"`); Password (`type="password"`, `autoComplete="new-password"`); Back (step 1, role and code kept); Create account -> hold, `signUp(email, password)` (skipped if already done), `register_3(role, code, displayName)`, then `setUser(user)`, release.
- **Finish setup** (`RegisterFinish.tsx`), shown when `session.status === 'unregistered'` and this component holds no hold: text "You are signed in as {firebaseEmail}, but your profile is not set up yet. You do not need to create the account again."; role group; Registration code (`type="password"`, `autoComplete="off"`); Display name; Finish -> `checkCode_2`, then `register_3`, then `setUser`; a "Sign out" `<button type="button">` -> `session.signOut()`.
- While `session.status === 'loading'` (and no hold), submit buttons are disabled.

**States** [contract] (exact text):
| Condition | Shown |
|---|---|
| 403 `REGISTRATION_CODE_INVALID` | "Code not accepted." under the code field; the step does not advance |
| 429 `RATE_LIMITED` | `banner b-warn` "Too many attempts. Try again in N seconds." (N = 1: "Try again in 1 second."), N = `retryAfterSeconds` or 60 when null; counts down once a second; submit disabled until 0, then the banner clears; continues across step changes; interval cleared on unmount |
| 409 `ALREADY_REGISTERED` | `banner b-bad` "This account is already registered. Sign in instead." with `<a href="/sign-in">Sign in instead</a>` |
| 422 `VALIDATION_FAILED` | each `details[i].message` under its field: `role` -> role group, `code` -> code field, `displayName` -> display name; any other `field` -> form banner |
| Firebase `auth/email-already-in-use` | Firebase's `message`, plus a "Sign in instead" `<a href="/sign-in">` |
| other Firebase error (has `code` starting `auth/`) | Firebase's `message` unchanged |
| `ApiError` `NETWORK`, `INTERNAL` or status >= 500 | "Something went wrong.", a Retry button that repeats the failed request, and "Request ID: {id}" when `requestId` is set |
| anything else (any other `ApiError` such as 401, 404 or another 4xx code, or a thrown value with no `auth/` code) | same as the row above |
