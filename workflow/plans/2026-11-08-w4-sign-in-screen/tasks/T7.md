## Objective
A fast test fails the build if anyone later imports Firebase elsewhere, calls `fetch` or `location.assign` outside their owners, reads non-public env in browser code, uses `dangerouslySetInnerHTML`, or pulls the server-only mode function into a client file.

## Rules that apply
- SD13 - the rules are a Vitest test, not an extension of `check-data-layer.mjs` (that script is not run in CI, and `ci.yml` is not edited).
- Scan every `.ts`/`.tsx` file under `src/fe/` except `node_modules/`, `.next/`, `test/` and `scripts/`.
- A "client file" is one whose first non-empty line is `'use client';` or `"use client";`, plus `lib/auth/firebase.ts` and `lib/auth/navigate.ts`.
- Each failure message names the file and line.
- Lines whose trimmed text starts with `//` or `*` are skipped for rules 1-5 (comments).

## Contract
`src/fe/test/source-rules.test.ts` [contract] (`// @vitest-environment node`, reads files with `node:fs`):

| Rule | Check | Allowed exceptions |
|---|---|---|
| 1 | no `from 'firebase` or `from "firebase` import | `lib/auth/firebase.ts` |
| 2 | no match of `/\bfetch\(/` | `lib/api/http.ts`; any file under `app/api/` |
| 3 | no `location.assign(` | `lib/auth/navigate.ts` |
| 4 | no `dangerouslySetInnerHTML` | none |
| 5 | in client files, every `process.env` use is one of the four literal `process.env.NEXT_PUBLIC_FIREBASE_(API_KEY|AUTH_DOMAIN|PROJECT_ID|APP_ID)`; no `process.env[` | none |
| 6 | no client file has a non-type import that resolves to `lib/auth/mode`: resolve each relative specifier (`'./mode'`, `'../lib/auth/mode'`, with or without `.ts`) against the file's directory and compare the result with `src/fe/lib/auth/mode`; only `import type { ... } from` is a type import (`import { type X } from` counts as non-type) | none |

Plus: every line of `src/fe/.env.example` that is not blank or a `#` comment matches `/^[A-Z0-9_]+=$/`.
