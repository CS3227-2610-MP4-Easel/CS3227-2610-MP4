## Objective
In `firebase` mode, every page waits for Firebase and `GET /api/me`, routes by the session status, and renders screens with the role from `/api/me`; the top bar shows that user and signs out through Firebase. `prototype` mode behaves exactly as today; `unconfigured` shows one line.

## Rules that apply
- SD1 - the gate is client-side; server files only compute the mode and pass `pathname`, `view`, `mode` as props.
- SD3 - the gate is the only owner of `replace('/projects')` after sign-in or registration.
- SD9 - a 401 from `me_4` changes nothing (sign-out is already under way; `onUserChanged(null)` follows).
- SD10 - `holdForRegistration` and a generation number keep the register step mounted through `signUp`.
- Redirects use `useRouter().replace` inside `useEffect`, never during render; while one is pending render the loading view.
- Import `AuthMode` with `import type` in client files; never import `authMode` into a client file.

## Contract
**`lib/auth/mode-context.tsx`** [contract] (`'use client'`): `AuthRoot({ mode, children }: { mode: AuthMode; children: ReactNode })` provides `AuthModeCtx`; `useAuthMode(): AuthMode` returns `'prototype'` outside it. `mode === 'unconfigured'`, or `mode === 'firebase' && !firebaseConfigured()` -> render only `<main className="app" style={{ alignItems: 'center', justifyContent: 'center' }}><p>Sign-in is not configured for this deployment.</p></main>`. `mode === 'firebase'` otherwise -> `<SessionProvider>{children}</SessionProvider>`; `prototype` -> children.

**`lib/auth/session.tsx`** [contract] (`'use client'`):
```ts
export type SessionStatus = 'loading' | 'signed-out' | 'unregistered' | 'ready' | 'error';
export type Session = { status: SessionStatus; user: User | null; firebaseEmail: string | null; error: ApiError | null;
  retry(): void; setUser(u: User): void; holdForRegistration(): () => void; signOut(): Promise<void> };
export function SessionProvider({ children }: { children: ReactNode }): JSX.Element;
export function useSession(): Session | null;            // null outside a provider
export function toRole(r: ApiRole): Role;                // PM->'pm', DEV_LEAD->'lead', DEVELOPER->'dev'
export const ROLE_LABEL: Record<ApiRole, string>;        // Project Manager, Dev Lead, Developer
export function initialsOf(displayName: string): string; // trim, split /\s+/, first code point of first two words, toUpperCase; '?' when none
```
State machine: starts `loading`. Each `onUserChanged` call increments a generation and restarts: null -> `signed-out`, user null; a user -> `firebaseEmail = u.email`, then if a hold is active and the previous user was null, keep the current status and stop; else `loading` and `me_4()`: 200 -> `ready` with the user; `ApiError` `USER_NOT_REGISTERED` (403) -> `unregistered`; status 401 -> no change; anything else -> `error` with the `ApiError`. A reply whose generation is not current is discarded. `retry()` -> `loading`, `me_4()` under the current generation. `setUser(u)` -> generation + 1, `ready`, `user = u`. `holdForRegistration()` increments a hold count and returns a release that decrements it (release calls nothing). `signOut()` -> `try { await signOutUser() } finally { hardNavigate('/sign-in') }`.

**`components/auth-gate.tsx`** [contract] (`'use client'`): `AuthGate({ pathname, view }: { pathname: string; view?: string })`. Public: `/sign-in`, `/register`, `/styleguide`, `/states`.

| Status | Protected route | `/sign-in` | `/register` | `/styleguide`, `/states` |
|---|---|---|---|---|
| `loading` | loading view | `<SignIn />` | `<Register />` | `Screen` with role `pm` |
| `signed-out` | replace `/sign-in` | `<SignIn />` | `<Register />` | same |
| `unregistered` | replace `/register` | replace `/register` | `<Register />` | same |
| `ready` | `Screen found={resolve(pathname, view, role)} role home={HOME[role]}`, role = `toRole(user.role)` | replace `/projects` | replace `/projects` | same |
| `error` | error view | error view | error view | same |

Loading view: `<main className="app" style={{ alignItems: 'center', justifyContent: 'center' }}><p>Loading…</p></main>`. Error view: `<p>Something went wrong.</p>`, a `<button className="btn p">Retry</button>` calling `retry()`, and `<p className="small muted">Request ID: {id}</p>` only when `error.requestId`. While a hold is active the status stays `signed-out` or `loading`, so the table already keeps `<Register />` on `/register`; no extra rule. The `/styleguide` and `/states` cells always use role `pm`, as today, whatever the user's role.
