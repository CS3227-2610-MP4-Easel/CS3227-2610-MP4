## Objective
Two additive gateway functions: `openOrReuse` returns a usable open session for (user, feature, project) or opens one; `recordCacheHit` writes one `llm_calls` row with status `CACHE_HIT` and never touches limits.

## Rules that apply
- AD-11 - the frozen `Sessions` type does not change; `openOrReuse` goes on `GatewaySessions` only.
- AD-18 - every cache hit writes one `CACHE_HIT` row (`src/be/llm-gateway/src/usage.ts` already counts them).
- `recordCacheHit` never admits a call, never calls the limiter (`hit`), the budget or the breaker.
- Every query stays limited to the runtime's tier (`env`), like the rest of `sessions.ts`.
- Preview runtime: both new functions throw `Error("AI_NOT_CONFIGURED")`, like the other preview session methods.

## Contract
**`openOrReuse({ feature, userId, projectId }): Promise<string>`** [contract] on `GatewaySessions`, in `createSessions`:
- Find this tier's `OPEN` sessions with the same `userId`, `feature` and `projectId`, newest `lastActivityAt` first. Return the first one for which `assertUsable(id, userId, feature)` does not throw (an idle one gets abandoned by `assertUsable`; keep looking).
- If none: call the same `open` implementation (a local function, not `this.open`, so a detached `openOrReuse` still works), with the same caps and `SessionCapReached` errors.
- Reusing does not change `lastActivityAt` (the gateway's `run` touches the session).
