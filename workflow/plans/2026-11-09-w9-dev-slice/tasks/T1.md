## Contract
**`standupActivityWindowFor(date: string, now: Date): { from: Date; to: Date }`** [contract], in `src/be/contracts/src/date-rules.ts`, exported from `@agile/contracts`: `src/be/contracts/src/index.ts` does not re-export `date-rules.js` today, so add `export * from "./date-rules.js";` (all its exports become public; check no name collides):
- `date` is a `YYYY-MM-DD` already validated by the caller.
- `from` = 00:00 `Asia/Singapore` (`+08:00`) of the last Monday-Friday calendar day strictly before `date`.
- `to` = `now`. When `from >= to` the window is empty; callers check that (no clamping here).

**`readLimitedBody(request: Request, maxBytes: number): Promise<{ tooLarge: true } | { tooLarge: false; text: string }>`** [contract] and **`contentLengthTooLarge(request: Request, maxBytes: number): boolean`** [contract], in new `src/be/api/src/body-limit.ts`:
- `contentLengthTooLarge`: true when a `Content-Length` header is all digits and its number is greater than `maxBytes`; never reads the body.
- `readLimitedBody`: first `contentLengthTooLarge`; then reads `request.body` chunk by chunk, summing `byteLength`; once the sum exceeds `maxBytes` it cancels the reader (not awaited, `.catch(() => {})`) and returns `{ tooLarge: true }`. Otherwise decodes the bytes as UTF-8 and returns the text. A body of exactly `maxBytes` bytes is accepted. A missing body returns `{ tooLarge: false, text: "" }`.
- `bodyTooLarge(request: Request, maxBytes: number): Promise<boolean>` [contract]: the same counting over `request.clone()` (for `before` hooks that must leave the body for later parsing). `auth.ts` imports this and passes `MAX_BODY_BYTES`; its local copy is deleted.

**Route body limit after authorisation** [contract] - route handlers get no raw `Request`, so the limit lives in registration:
- `src/be/contracts/src/routes.ts`: add an optional field to `RouteDefinition`, `/** Read the body only after authorization, stopping past this many bytes (413). */ bodyLimitBytes?: number;`. Nothing else changes.
- `src/be/api/src/routes/register.ts` (`registerRoute`, the `body:` line inside `input`): when `route.bodyLimitBytes` is set and `route.bodySchema` is a schema, read the body with `readLimitedBody(c.req.raw, route.bodyLimitBytes)` instead of `parseJsonBody`: `tooLarge` → `throw new HttpError("PAYLOAD_TOO_LARGE", 413, "The request body is too large.")`; then apply `parseJsonBody`'s rules to the text (content type must start with `application/json`, else 400 `BAD_REQUEST` "Request content type must be application/json."; `JSON.parse` failure → 400 `BAD_REQUEST` "Request body is not valid JSON."), then `parseInput(route.bodySchema, value)`. Routes without `bodyLimitBytes` behave exactly as before. This still runs after `authorizeRequest`, so an unauthenticated request never has its body read.

**`src/be/core/src/index.ts`** [contract]: add `lockProjectForMutation` to the existing `export { createCore, ... } from "./core.js";` line. Nothing else in `src/be/core` changes.
