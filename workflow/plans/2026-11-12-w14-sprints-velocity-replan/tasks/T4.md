# T4: W8 digest persistence through ProposalService

**Delivers:** W8 digest flow uses proposal owner for creation/supersession and preserves zero-velocity forecast semantics | **Satisfies:** F8, N2, N4, E25, E27 | **Depends on:** T3 | **Wave:** 3 | **Weight:** complex | **Review:** full (Attacker lens required for AI session/proposal atomicity)

## Expected state
- T3 extends the merged ProposalService with REPLAN creation and transaction-aware session closure.
- `src/be/lead/src/flow.ts` directly creates `tx.aiProposal` and closes sessions after persistence.
- Existing digest facts, output validation and degraded behavior must remain unchanged.

## Objective
Refactor W8 digest persistence so `lead` owns facts/digest façade only, while ProposalService creates/supersedes REPLAN proposals and binds/updates sessions in the same transaction as digest persistence. The existing lead transaction callback owns the complete flow: it creates the digest, calls `createReplanInTransaction(tx, ...)`, updates `projectDigest.proposalId`, invokes the injected `TransactionSessionCloser.closeInTransaction` for superseded/current sessions, and commits once. Remove the current post-commit close and every direct `tx.aiProposal` access from lead.

## Rules that apply
- Project → proposal → session lock order applies to concurrent digest/approve/reject.
- Proposal payload stores original suggestions/explanation; creation validates project/actor/session binding.
- Existing W8 AI degraded response and session caps remain unchanged.

## Contract
[contract] A successful digest with suggestions creates one PENDING REPLAN proposal; a prior pending proposal becomes SUPERSEDED and its OPEN session closes REJECTED. The exact transaction sequence is `projectDigest.create(tx)` → `proposalService.createReplanInTransaction(tx, {projectId, sessionId, ownerId, actorId, suggestions, explanation})` → `projectDigest.update({proposalId})` → `sessionCloser.closeInTransaction(tx, ...)` → commit. `lead` does not query or mutate `ai_proposals`. `projectCompletion` returns null for zero/null average velocity; remaining-work risk is UNKNOWN and zero-remaining risk is ON_TRACK.
