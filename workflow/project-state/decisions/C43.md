# C43 — Make the trusted workflow the authoritative security status

- **Date:** 2026-11-05.
- **Who asked:** Codex review of the T7 amendment, accepted by the operator's implementation
  approval.
- **Decision:** The PR-controlled `workflow-security-pr` job is non-authoritative. The trusted
  workflow owns the required `workflow-security` context and runs on PR synchronization plus review
  submission, edit, and dismissal; stale review-event heads fail closed.
- **Why:** Two jobs publishing the same required context would leave GitHub without a clear status
  authority and could preserve a passing result from the PR-controlled workflow.
