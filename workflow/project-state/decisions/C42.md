# C42 — Re-evaluate review approvals in a separate trusted workflow

- **Date:** 2026-11-05.
- **Who asked:** operator (Dev Lead), confirming the recommended design for findings 2–5.
- **Decision:** Keep the existing `pull_request` workflow for ordinary checks and add a separate
  `pull_request_review` workflow, stored on the trusted base branch, for review submission/edit/
  dismissal events. The review workflow evaluates the PR head as data and publishes the same
  security-review status context.
- **Why:** Review changes must invalidate or satisfy the gate without executing PR-controlled
  enforcement code. Combining both triggers in the PR-controlled workflow would preserve the
  stale-approval problem and blur the trusted/untrusted execution boundary.
