# D2 — Authorization precedes input parsing (W1 route seam)

- **Date:** 2026-11-03
- **Workstream:** W1
- **Still live:** yes — the code still behaves this way

## What the Document Said

The route pipeline described parsing path, query, and body before role and membership checks.

## What Is True Instead, and Why

`registerRoute` authorizes first because authorization bundles role, resource resolution, and membership. Resolvers receive `body: undefined`, and malformed requests can receive 401/403/404 before 422.

## Consequence

Resolvers must not depend on parsed `context.input`; handlers read parsed values after authorization.
