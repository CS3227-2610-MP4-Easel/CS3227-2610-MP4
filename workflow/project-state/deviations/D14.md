# D14 — A Firebase public-key fetch failure is recognised by its message (W4 T3)

- **Date:** 2026-11-04
- **Workstream:** W4
- **Still live:** yes — the code still behaves this way

## What the Document Said

Spec E45 mapped every `auth/argument-error` to `InvalidToken`.

## What Is True Instead, and Why

With outbound HTTPS blocked, `firebase-admin` 13.10 reports the failed key fetch as `auth/argument-error` with the message "Error while making request: …", so a Google outage would have returned 401 and looked like a sign-out, against E29. The adapter now maps that message to `VerifierUnavailable` (500); every other `auth/argument-error` stays `InvalidToken`. E45 gained the case in the spec and the test.

## Consequence

If a `firebase-admin` upgrade changes that message, outages become 401 again; the E45 test pins the current text, so re-run the blocked-network check (`sandbox-exec` denying TCP 443) after any upgrade.
