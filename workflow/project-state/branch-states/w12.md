  submission, edit, and dismissal; stale review-event heads fail closed.
- **Why:** Two jobs publishing the same required context would leave GitHub without a clear status
  authority and could preserve a passing result from the PR-controlled workflow.

- **What:** The GitHub Node 20 runner does not expand the quoted recursive test globs accepted by the local Node 22 runner, and the original historical test canary remains in the PR commit range.
- **Consequence:** The workspace test job failed to discover tests, while exact Gitleaks 8.24.2 correctly detected the old non-secret redaction fixture.
- **Action:** Switched `npm test` to portable `find`-based file discovery, replaced the current canary with a generic fixture value, and added one exact reviewed Gitleaks fingerprint to `.gitleaksignore`, protected by CODEOWNERS. Exact pinned scanning, all 114 tests, typecheck, lint, contracts, workflow validation, and dependency audit pass locally.

### D~3 — First PR run exposed CI-only prerequisites

- **Date:** 2026-11-04
- **What:** The first clean GitHub PR run failed because `npm ci --ignore-scripts` did not generate Prisma Client, Prisma config had no `DATABASE_URL`, and the runner did not have the pinned Gitleaks binary installed.
- **Consequence:** Local checks were green only because the local environment had generated Prisma artifacts and a different Gitleaks version; the required PR checks were not self-contained.
- **Action:** Added a non-secret placeholder `DATABASE_URL` at workflow scope, explicit Prisma generation in the workspace/typecheck/lint jobs, and a checksum-pinned Gitleaks 8.24.2 install step. Added regression assertions for each prerequisite.

## 9. Lessons

- **L~1 — CI security specs need enforcement seams, not only control names:** The first draft named required controls but left check topology, policy evaluation, fork isolation, and protected settings implicit; cause was treating the architecture summary as an implementation contract; rule is to specify the evaluator, command, protected path, and observable failure for every process-security control; scope `role:spec-writer`; found by Implementer, Tester, Maintainer, and Attacker review.

### L~2 — workflow controls must parse their target format

- **Date:** 2026-11-04
- **Cause:** The PR's workflow checker matched raw YAML lines, so quoted keys and block scalars bypassed action, permission, and trigger checks.
- **Rule:** Security validators must parse the target format structurally and include adversarial syntax fixtures; line matching is not an enforcement boundary.
- **Scope:** project
- **Found by:** Codex review of PR #9

### L~3 — security controls must be enforced at the execution boundary

- **Date:** 2026-11-04
- **Cause:** The mediation seam was added as a command in generated adapter prose, but no provider/runtime wrapper invokes it before tool execution.
- **Rule:** A process-security control is incomplete until the actual execution boundary cannot bypass it; a documented command and unit probe are not enough.
- **Scope:** project
- **Found by:** Codex re-review of PR #9

### L~4 — execution-boundary mediators must fail closed on unknown mutations

- **Date:** 2026-11-04
- **Cause:** The provider hook classified unrecognized Bash commands as repository reads and treated unnormalized or external paths as ordinary repository writes; its own hook files were not in the mediation review set.
- **Rule:** Unknown shell commands, external paths, traversal paths, and changes to the mediator/control-plane files must be denied or review-required before execution.
- **Scope:** project
- **Found by:** Codex re-review of the committed W12 fixes

### L~5 — safe-read allowlists must validate command operands

- **Date:** 2026-11-04
- **Cause:** The Bash classifier allowed a known read command as a repository read without checking whether its path arguments pointed outside the repository.
- **Rule:** A command allowlist must validate both the executable and every path-bearing operand; absolute, home-relative, and traversal paths fail closed.
- **Scope:** project
- **Found by:** Codex adversarial re-review of the local fixes

### L~6 — command allowlists must name approved scripts

- **Date:** 2026-11-04
- **Cause:** The Bash classifier allowed every npm workspace script by shape, so a mutating script could be introduced without changing the mediator.
- **Rule:** Allow only explicitly approved script names; a command that merely matches a safe-looking wrapper shape is not a safe operation.
- **Scope:** project
- **Found by:** Codex adversarial re-review of the local fixes
