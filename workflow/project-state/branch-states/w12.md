## 8. Deviations

### D~1 — W12 baseline is red before implementation

- **Date:** 2026-11-03
- **What:** `npm test` passes, but `npm run typecheck` and `npm run lint` fail because W1 contract declaration output has not been built; `npm --workspace @agile/db run prisma:validate` fails because `DATABASE_URL` is unset.
- **Consequence:** T1 cannot start under the execution precondition requiring a green baseline. No W12 implementation files have been created.
- **Action:** Forced the TypeScript build, reinstalled the committed lockfile dependencies, added explicit Prisma generation before workspace tests, and verified the full baseline. The missing `DATABASE_URL` remains a validation-input requirement; a local placeholder URL is sufficient and no database connection is made.
- **Resolution:** Resolved for local and CI verification; retain the placeholder `DATABASE_URL` convention for schema validation and run explicit Prisma generation after `npm ci --ignore-scripts`.

### D~2 — Security remediation required Prisma 7 compatibility work

- **Date:** 2026-11-04
- **What:** The first fixed Prisma release was 7.10.1, which removes schema datasource URLs and requires a PostgreSQL driver adapter; Prisma 7 also omits relation-list cardinality from the runtime DMMF used by one existing invariant test.
- **Consequence:** T3 required `prisma.config.ts`, the `@prisma/adapter-pg` client path, compatible test construction, and a guarded cardinality assertion when the runtime metadata is unavailable.
- **Action:** Preserved `DATABASE_URL` as the config source, added the adapter, retained Zod v3 semantics through Zod 4's compatibility entrypoint, and verified the complete W1/W12 test suite.

### D~3 — First PR run exposed CI-only prerequisites

- **Date:** 2026-11-04
- **What:** The first clean GitHub PR run failed because `npm ci --ignore-scripts` did not generate Prisma Client, Prisma config had no `DATABASE_URL`, and the runner did not have the pinned Gitleaks binary installed.
- **Consequence:** Local checks were green only because the local environment had generated Prisma artifacts and a different Gitleaks version; the required PR checks were not self-contained.
- **Action:** Added a non-secret placeholder `DATABASE_URL` at workflow scope, explicit Prisma generation in the workspace/typecheck/lint jobs, and a checksum-pinned Gitleaks 8.24.2 install step. Added regression assertions for each prerequisite.

- **L~1 — CI security specs need enforcement seams, not only control names:** The first draft named required controls but left check topology, policy evaluation, fork isolation, and protected settings implicit; cause was treating the architecture summary as an implementation contract; rule is to specify the evaluator, command, protected path, and observable failure for every process-security control; scope `role:spec-writer`; found by Implementer, Tester, Maintainer, and Attacker review.
