## 6. Known Gaps

- **`$queryRawTyped` is still reachable on the request-facing client** — `src/be/db/src/client.ts` hides `$queryRaw`, `$queryRawUnsafe`, `$executeRaw`, `$executeRawUnsafe` and `$extends`, but not Prisma's typed-SQL entry point `$queryRawTyped` (a function on the filtered client under Prisma 6.19). It is not exploitable while the `typedSql` preview feature is off and no `.sql` files exist, but enabling either bypasses every visibility rule. Add it to `RAW_SQL_METHODS`, the `RawSqlMethodName` type and the raw-query-boundary test before anyone enables typed SQL. Warning, carried into the project state.
- **Relation filters in a caller's `where` can see soft-deleted rows** — the filtered client restricts the target model and its selected relations, not filters on relations, so `project.findMany({ where: { tasks: { some: { title } } } })` matches through a soft-deleted task. Never build `where` clauses from request input without validating them.
- **Nested writes are not authorized by the client** — connecting a new task to a soft-deleted epic succeeds. Callers must check every connected id inside the mutation transaction (comment on `createDbClient`).

## 8. Deviations

- **D~1 — Authorization runs before input parsing (T6 route seam):** the spec's pipeline parses path/query/body before the role and membership checks, but `authorizeRequest` bundles role, resource resolution and membership, so `registerRoute` authorizes first and parses afterwards. A malformed request therefore gets 401/403/404 before 422, and resolvers receive `body: undefined`. This hides existence better and is harmless for validation, but a resolver that needs the body must read it itself.
- **D~2 — `registerRoute` takes the app and dependencies:** the spec says `registerRoute(route)`; the shipped form is `registerRoute(app, route, deps?)` in `src/be/api/src/routes/register.ts`, with a per-app registry, and `createApiApp(deps)` registers the `ROUTES` list. A non-public route without `deps` throws at registration.
- **D~3 — Minimal Next health adapter in `src/fe` (C~7):** `src/fe/app/api/[[...route]]/route.ts` forwards every method to the Hono app, so PR #6's frontend tree gains one file although W1 otherwise leaves `src/fe` untouched.
